# Integration contract

Use `AddressSpace(capacity)` for deterministic map, protect, unmap, and access checks. Storage is inline and mutations are failure-atomic. Use `ExecPlan(segment_capacity, interp_capacity).prepare` to stage a main ELF and optional interpreter; project 54 validates both. The returned plan owns copied interpreter-path bytes and inline load plans. The plan derives PT_INTERP from validated main-image bytes; the caller resolves that exact path through its filesystem, builds the initial stack with project 55, maps pages with project 49, and commits only after complete validation.

Use `MaterializedImage(page_capacity).prepare(bytes, load_plan, bias)` during PREPARE to produce an allocation-free owned set of zero-initialized pages. It iterates every planned segment, handles unaligned first and final pages, copies exact file bytes, leaves BSS and untouched bytes zero, merges shared-page permissions without permitting W+X, and fails explicitly on address overflow, source drift, or page capacity. `PreparedImage(page_capacity).prepare(..., backing)` instead writes into an explicit caller-owned bounded reservation and returns only page metadata, allowing large machine-policy arenas to remain outside an inline kernel value. Insufficient backing fails during PREPARE. The caller reserves physical backing, copies these prepared pages through supervisor access, and installs only their final permissions during COMMIT.

This module does not decode Linux mmap/exec flags, allocate physical pages, mutate page tables, parse PT_INTERP from raw program headers, relocate ELF objects, or promise a stable ABI.

# Governance

The repository currently operates honestly as a single-maintainer project; no committee or guaranteed response time is implied. The repository owner has merge, release, schema, stability, and security-triage authority. CODEOWNERS records review routing, not proof of independent review.

Ordinary compatible modules follow existing contracts. RFCs and owner approval are required for schemas, canonical sources, naming/ownership policy, repository-wide migrations, maturity policy, and breaking build architecture. Breaking stable contracts require migration and dependent review. Disputes are resolved from source, tests, accepted ADRs, and evidence; unresolved policy questions use an RFC. Abandoned modules may be reassigned by the owner with history preserved. Succession is recorded by updating CODEOWNERS, release authority, and this document before credentials or duties change.

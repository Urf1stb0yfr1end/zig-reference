PART D — REPAIR THE DEVELOPER MINIMUS EXECUTION MODEL

Preserve the permanent Minimus philosophy already added to AGENTS.md:

- ordinary output is preserved;
- LOCATIONS is appended after ordinary output;
- MINIMUS follows LOCATIONS;
- Minimus is at most 200 lines and normally much shorter;
- literal durable `file:///absolute/path` locations must point to existing useful paths;
- Minimus never masks a failure or changes the underlying truth.

But refine the implementation so the developer sees exactly ONE authoritative top-level handoff for the serious command they intentionally invoked.

The independent review proved the current flaw:

- `zig build smoke --summary all` prints LOCATIONS/MINIMUS from a child build step, then Zig prints its Build Summary afterward, so Minimus is not literally the final developer handoff;
- `zig build validate-repository --summary all` can execute the smoke child and display `MINIMUS status: PASS command: zig build smoke`, then later fail because another prerequisite failed. That subordinate PASS is visually misleading inside the failed outer command.

Required semantics:

PUBLIC SERIOUS COMMAND
  normal existing output
  final normal summary / failure output
  LOCATIONS
  MINIMUS for THIS outer command
  process exits with the original command's exit status

There must not be nested public Minimus blocks from prerequisites when a serious aggregate calls another covered check internally.

Do not try to fake "after Zig's own Build Summary" from a child build step if Zig itself prints the Build Summary only after that child exits. Choose an architecture that can actually satisfy the requirement.

A preferred direction is one compact canonical developer wrapper/driver that:

1. invokes the existing underlying Zig/Python command;
2. lets/copies its ordinary output through unchanged;
3. waits for the underlying process to finish;
4. records the real exit code;
5. appends LOCATIONS and exactly one MINIMUS for the requested outer operation;
6. exits with the original underlying status.

Use one small reusable interface, not five unrelated wrappers. Choose the exact command spelling based on existing repository conventions and keep it simple.

If a wrapper becomes the canonical developer-facing handoff surface, preserve the raw `zig build ...` commands as valid underlying implementation commands. Do not lie that raw Zig can print after its parent process's own final summary if it cannot.

Update AGENTS.md so the permanent Minimus rule accurately distinguishes:

- raw implementation/build commands;
- canonical serious developer handoff commands;
- nested prerequisite/check steps that MUST NOT emit misleading subordinate Minimus blocks.

Update COMMANDS.md with the exact canonical developer commands and their purpose.

The following serious operations must have a canonical Minimus-producing developer surface after this repair:

- Agent Fast Path doctor
- aggregate smoke
- complete repository validation
- Morphic plan verification
- Morphic trace verification

For direct `agent doctor`, retaining its existing JSON followed by LOCATIONS then MINIMUS is acceptable if it remains truly at the end of that Python command and is not duplicated by another wrapper.

For build-backed operations, prove the top-level Minimus occurs after the complete underlying command output, including any Zig Build Summary when `--summary all` is part of the canonical invocation.

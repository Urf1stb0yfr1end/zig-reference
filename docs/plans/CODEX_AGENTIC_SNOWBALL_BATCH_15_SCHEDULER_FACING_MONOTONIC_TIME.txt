CODEX AGENTIC SNOWBALL BATCH 15 — SCHEDULER-FACING MONOTONIC TIME

MISSION

Extend the now-proven Batch 14 RISC-V timer boundary by exactly one semantic bridge:

CONNECT REAL SUPERVISOR-VISIBLE MONOTONIC TIME TO THE EXISTING BOUNDED DETERMINISTIC SCHEDULER WITHOUT INTRODUCING PREEMPTION, CONTEXT SWITCHING, GENERIC CLOCK APIs, OR LINUX/POSIX TIME CLAIMS.

Batch 14 proved that the freestanding RISC-V machine can:

OpenSBI
→ enter our S-mode payload
→ use our direct stvec boundary
→ preserve the existing fixed TrapFrame
→ take multiple real asynchronous supervisor timer interrupts
→ observe strictly monotonic rdtime values
→ explicitly re-arm each non-final timer event
→ return through sret after every expected delivery
→ explicitly neutralize the final event
→ reject extra delivery
→ preserve Batch 12 and Batch 13 proofs
→ preserve the canonical Morphic bytes

The repository already contains a reusable target-neutral scheduler:

projects/52-bounded-deterministic-scheduler

That scheduler was intentionally designed around caller-controlled monotonic time and stable deterministic ordering. Batch 08 already records time monotonicity as one of its canonical invariants.

Batch 15 asks the next narrow question:

CAN REAL MONOTONIC MACHINE TIME BE FED THROUGH A SMALL TRUTHFUL ADAPTER INTO THE EXISTING TARGET-NEUTRAL SCHEDULER SO THAT SCHEDULED WORK BECOMES READY AT PROVEN MACHINE-OBSERVED TIMES, WHILE THE INTERRUPT HANDLER REMAINS NON-PREEMPTIVE AND THE SCHEDULER RETAINS ITS EXISTING DETERMINISTIC SEMANTICS?

The intended bridge is:

real RISC-V rdtime
→ small machine-time observation boundary
→ explicit monotonicity validation
→ existing BoundedDeterministicScheduler time input
→ scheduler advance / readiness decision outside interrupt context
→ deterministic ready-task selection
→ evidence relating real observed time to scheduler-visible time
→ unchanged Morphic semantics

Do not leap ahead.

This is NOT a preemption batch.
This is NOT a context-switch batch.
This is NOT a sleep syscall batch.
This is NOT a POSIX clock batch.
This is NOT a Linux compatibility batch.
This is NOT an Alpine boot batch.

It is the smallest trustworthy bridge between a proven hardware-emulated time source and an already-existing target-neutral scheduling primitive.

SEMANTIC REQUIREMENT

The scheduler must continue to own scheduling semantics.
The machine adapter must only provide truthful machine observations and narrow orchestration.

INTERRUPT-CONTEXT RULE

Batch 15 must remain non-preemptive.

The timer handler may:

- record bounded evidence;
- capture the real monotonic counter value;
- perform the already-required timer re-arm or neutralization policy;
- update the minimum bounded state required to communicate an observation to normal supervisor execution.

The timer handler must NOT:

- execute arbitrary scheduled tasks;
- invoke general task callbacks;
- context-switch between tasks;
- mutate scheduler queues through a broad hidden path unless the scheduler's contract explicitly allows interrupt-context use and the repository can prove the required invariants;
- allocate;
- block;
- perform unbounded loops;
- claim preemption.

Prefer scheduler advancement and ready-task selection after sret, in normal S-mode execution, using the recorded machine observation.

If the exact implementation can safely be even narrower, choose the narrower design.

OVERFLOW AND MONOTONICITY POLICY

Batch 14's bounded proof uses wrapping arithmetic when forming future timer deadlines, while its verifier requires the demonstrated deadline sequence itself to remain strictly monotonic.

Batch 15 must inspect this deliberately.

Do not silently promote wrapping arithmetic into a reusable scheduler-time policy.

For the scheduler-facing bridge, define and prove an explicit bounded policy for any conversion/addition that could overflow the scheduler's time representation.

Acceptable outcomes include, depending on existing contracts:

- use the raw observed machine counter directly when no addition is needed;
- checked conversion with explicit failure;
- checked/saturating operation if and only if that matches declared semantics;
- retain wrapping behavior only inside the narrowly bounded machine timer experiment while preventing it from being presented as a generic scheduler clock guarantee.

The resulting behavior must be documented as a contract, not left as accidental integer behavior.

Do not redesign Batch 14 merely to make this task larger. Harden only what the new bridge actually requires or what current proof exposes as unsound.


MINIMUM EXECUTABLE SCENARIO

Create the smallest bounded scenario that proves the bridge.

The proof should contain several scheduler entries with distinct ready times chosen so that the real machine observations cross meaningful readiness boundaries.

Example shape only; discover the existing scheduler API and use its native semantics:

- task A becomes ready at scheduler time threshold A;
- task B becomes ready at later threshold B;
- task C shares a threshold or otherwise exercises the scheduler's existing stable ordering rule;
- real supervisor timer observations provide monotonically increasing scheduler-visible times;
- after each returned timer event, normal S-mode code advances/consults the scheduler;
- tasks that are not yet eligible remain not-ready;
- newly eligible tasks become visible exactly when the scheduler contract says they should;
- selected ready tasks follow the existing stable deterministic ordering semantics.

Do not require the real rdtime values to equal fixed golden constants. They are relational evidence.

The proof must establish relationships such as:

machine_time[0] < machine_time[1] < ...

scheduler_time[i] corresponds to the declared mapping from machine_time[i]

scheduler_time never moves backward

readiness before threshold = false
readiness at/after threshold = true

stable ready ordering = existing scheduler contract

No fabricated software-only time increments may stand in for the real machine observations in the real-QEMU proof.

A fake/hosted path may continue to use deterministic synthetic time for target-neutral tests. That is desirable. The real-machine proof must show the scheduler bridge actually consumed values derived from the machine observations.

NO PREEMPTION

This requirement is strict.

A timer interrupt must not directly switch the currently executing task.

Batch 15 success should look conceptually like:

interrupt
→ record real time
→ re-arm/neutralize as declared
→ restore context
→ sret
→ normal supervisor execution
→ feed observation to scheduler
→ scheduler computes readiness
→ bounded proof action

NOT:

interrupt
→ scheduler picks another task
→ trap return resumes a different execution context

The latter belongs to a future preemption/context-switch batch and requires substantially stronger context, stack, privilege, and scheduling proofs.

LONG-HORIZON ALPZ DIRECTION

The long-horizon direction remains:

KEEP ALPINE. REPLACE LINUX.

FAMILIAR OUTSIDE. EXPLICIT INSIDE.

A future Alpz kernel needs truthful time to support sleeping, timeouts, maintenance, scheduling, process accounting, and eventually Linux-compatible clock behavior.

But Linux compatibility names are earned by semantic equivalence.

This batch should therefore build the internal machine→scheduler evidence bridge first, without prematurely calling it a Linux clock.

→ physical-memory ownership

→ U-mode
→ syscall boundary

Batch 15 strengthens the first line. It does not skip the others.

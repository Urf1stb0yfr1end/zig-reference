CODEX AGENTIC SNOWBALL BATCH 11 — FREESTANDING RISC-V EXECUTION BOUNDARY

MISSION

Remove Linux userspace from beneath the already-proven Morphic execution path without rewriting settled Morphic semantics.

Batch 10 proved that the existing shared Morphic core can compile as real riscv64-linux-musl machine code, execute under qemu-riscv64 Linux user-mode, and produce canonical bytes identical to native hosted and fake execution.

Batch 11 asks exactly one new question:

CAN THE SAME SETTLED MORPHIC SEMANTICS EXECUTE AS A REAL FREESTANDING RISC-V PAYLOAD WHEN LINUX USERSPACE NO LONGER PROVIDES PROCESS ENTRY, STDOUT, EXIT, STACK/BOOTSTRAP, OR DEFAULT HOSTED RUNTIME BEHAVIOR?

Governing principles:

ONE CORE.
SAME SCENARIO.
NO LINUX USERSPACE.
SMALLEST EXPLICIT MACHINE BOUNDARY.
STANDARD INTERFACES BEFORE PRIVATE ONES.
MECHANICAL EVIDENCE.
FAIL CLOSED.
MAXIMUM CERTAINTY PER TOKEN.

The strongest result may again be very little new code.


LONG-HORIZON DIRECTION — ALPZ

The long-horizon system, provisionally called Alpz, is intended to preserve familiar Linux/Alpine/POSIX-facing expectations while replacing increasingly more of the implementation beneath them with a Zig-native, agent-native substrate.

The design law is:

FAMILIAR OUTSIDE.
EXPLICIT INSIDE.

Future engineers and agents should reuse established concepts where compatibility requires them: ELF, POSIX/Linux process and file semantics, musl expectations, sockets, mmap, signals, futexes, epoll, conventional filesystem paths, Alpine tooling, apk, and the broader Alpine package ecosystem.

Internally, Alpz should minimize Cost of Correct Use through canonical components, explicit ownership/invalidation, ordinary terminology, small dependency closures, machine-readable contracts, focused validation, precise diagnostics, explicit unknowns, and aggressive elimination of One-Sentence Preventables and Silent-Failure Cascades.

Batch 11 does NOT implement that compatibility surface.

Do not begin POSIX/Linux syscalls, musl, Alpine init, apk, userspace ELF loading, processes, Linux kernel boot, Linux guest boot, a new kernel, a hypervisor, broad virtual-memory work, VirtIO, networking, or a universal HAL.

This batch is one machine-pressure step toward that future.

Do not invent an Alpz-specific concept when ordinary Zig, RISC-V, SBI, ELF, firmware, or emulator terminology already names it correctly.

Do not replace a conventional standard boundary merely for purity. Novel implementation is valuable; gratuitous interface novelty is not.

PHASE 0 — REPAIR TWO KNOWN BATCH 10 ROBUSTNESS GAPS BEFORE RELYING ON ITS VERIFIER

The merged Batch 10 verifier is technically useful, but its source exposes two small robustness defects that matter to an agent-native repository.

If they are still present on the supplied baseline, repair them narrowly before treating the verifier as a durable Batch 11 prerequisite:

1. QEMU USER-MODE EXECUTION TIMEOUT

   The Batch 10 verifier invokes qemu-riscv64 through subprocess.run without a timeout.

   A foreign executable that hangs must not consume unbounded wall time, agent compute, or tokens.

   Add a finite, clearly named timeout to the emulated execution path. Choose a conservative value appropriate for this tiny scenario rather than a brittle near-zero deadline. If existing tool conventions support a configurable timeout cleanly, use them; otherwise keep the mechanism simple.

   Timeout must produce deterministic failure and the normal Developer Minimus failure handoff.

   Do not impose arbitrary short timeouts on compilation merely because the emulator run is bounded.

2. READELF MACHINE-FIELD PARSING

   The Batch 10 verifier recognizes RISC-V using the exact padded English substring:

   Machine:                           RISC-V

   Replace that brittle spacing dependency with a small field-oriented or whitespace-insensitive parse of the Machine field while preserving the semantic requirement that the artifact identify as RISC-V.

   Do not add a parsing framework for this.

These are Batch 10 hygiene repairs, not a semantic rewrite and not permission to alter its Linux-userspace proof.

Add the smallest regression coverage practical for both behaviors.

Record them as One-Sentence Preventables removed by Batch 11.

ROOTFS TRANSPORT ARCHITECTURE

Implement the smallest GENERAL mechanism that lets a caller supply an immutable bounded filesystem namespace to the Morphic runtime.

Prefer reusing/generalizing Project 58 bounded-filesystem concepts rather than introducing an Alpine-specific VFS.

The neutral representation should model only what the exact pressure and reusable filesystem abstraction require, for example:

- directory objects
- regular-file objects backed by immutable caller bytes
- symbolic-link objects with bounded targets
- deterministic root-relative parent/child relationships
- bounded path components
- explicit object/data capacities
- exact checked byte ranges/offsets for regular files

Do not import Linux file descriptors, errno values, inode policy, mount namespaces, permissions databases, page cache, dentry cache, journaling, or general VFS machinery into the neutral representation merely because Linux has them.

The exact measured 517 objects and 7,069,903 regular-file bytes are PRESSURE MEASUREMENTS, not permanent Morphic architectural constants.

Capacity policy must therefore be explicit and bounded but general:

- caller/build-selected capacity is acceptable
- checked compile-time or construction-time capacity is acceptable
- fail closed if the supplied exact rootfs exceeds the chosen capacity
- do not silently truncate
- do not blindly make a permanent constant equal to 517 or 7,069,903
- do not inflate unrelated kernel image arrays merely to fit the rootfs

Prefer a distinct caller-owned/read-only transport or backing region rather than embedding ~7 MiB of rootfs data into the ordinary kernel image if doing so would recreate prior layout pressure.

All ranges must be page/range checked and must not overlap kernel, fixture, prepared-image, caller-artifact, stack, or other reserved domains.

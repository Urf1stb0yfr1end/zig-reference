======================================================================

Build the permanent interactive-I/O foundation that moves Morphic toward
PLAYABLE ALPINE without creating an Alpine-shaped kernel.

The priority is NOT to make `/ #` appear as quickly as possible.

  build once -> reuse forever

The mechanism produced here should remain useful for:
- real Alpine /bin/sh now;
- later Alpine processes, pipes, redirection, and apk;
- other Linux-compatibility programs;
- QuirkM native userspace;
- deterministic tests;
- QEMU today;
- future real hardware console backends.

If the correct reusable design takes longer than a shell-specific shortcut,
choose the reusable design.

North star:

  minimum permanent mechanism, maximum inherited civilization

======================================================================
3. ARCHITECTURAL TARGET — NEUTRAL MORPHIC BYTE STREAM
======================================================================

Create or extend a neutral Morphic mechanism for byte-oriented process I/O.

Desired conceptual shape:

  producer / device / fixture
           |
           v
   neutral Morphic byte stream/resource
           |
           +---- deterministic fixture backend
           |
           +---- live QEMU console backend
           |
           +---- future real-hardware backend
           |
           v
   process resource binding
           |
           v
   Linux ABI adapter (read/write/ioctl as required)
           |
           v
   unchanged Alpine userspace

The neutral mechanism must NOT contain:
- Linux syscall numbers;
- Linux errno values;
- BusyBox names or hashes;
- Alpine paths;
- RISC-V register conventions;
- terminal ioctl command numbers;
- QEMU-only assumptions in the semantic core.

Platform-specific console acquisition belongs in a platform/backend layer.
Linux-specific behavior belongs in the Linux compatibility edge.

The core should express only reusable concepts such as:
- readable byte source / writable byte sink;
- bounded transfer;
- resource identity/lifetime;
- blocking/not-ready/end-of-stream semantics if real pressure requires them;
- explicit capability checks;
- deterministic failure.

Prefer composition with the existing Morphic semantic operation/resource model
rather than inventing a parallel I/O universe.

======================================================================
4. REQUIRED BACKEND SEPARATION
======================================================================

The deterministic fixture and live console must be separate backends behind the
same neutral interface.

Regression fixture:
- remains deterministic;
- keeps existing tests reproducible;
- does not share cursor/state accidentally with external Alpine execution;
- can still serve synthetic syscall probes.

Live console:
- receives real host/QEMU keyboard input;
- sends real process output to the existing machine console path;
- is selected explicitly for the external interactive process;
- does not require Alpine-specific code.

Do not globally replace the fixture with live UART input. Tests must remain
hermetic.

Do not make one global mutable stdin cursor the process-I/O architecture.
Ownership/state should follow the resource/backend instance.

======================================================================
5. LIVE CONSOLE IMPLEMENTATION RULE
======================================================================

Inspect the existing freestanding platform I/O path before choosing a transport.
Use the smallest correct existing QEMU/firmware mechanism that can support
receiving bytes without polluting the semantic core.

Candidate implementation details may include SBI debug-console/legacy input or
the QEMU virt UART, but do NOT assume one in advance if the repository already
has a better abstraction.

Whatever backend is chosen, isolate it so that a future real-hardware console
backend can implement the same neutral stream contract without changing process
or Linux-compatibility semantics.

Avoid an unbounded busy-spin if a correct bounded wait/read model is already
available or naturally required by the machine architecture. If blocking input
requires a new wait/readiness concept, implement the smallest reusable semantic
mechanism and document why it belongs in Morphic rather than in Linux glue.

Immediately after the focused proof, retry the SAME exact Alpine `/bin/sh`.

======================================================================
8. TTY / IOCTL POLICY
======================================================================

An interactive shell may probe terminal state using Linux ioctl/termios calls.
Do not pre-implement a broad terminal subsystem from a checklist.

If unchanged Alpine pressure proves a specific terminal semantic is blocking:
- record the exact observed syscall and arguments;
- identify the user-visible semantic BusyBox actually depends on;
- express reusable terminal/console state neutrally where appropriate;
- translate Linux ioctl command/struct encoding only at the Linux edge;
- implement only the minimum real semantic required;
- retry unchanged `/bin/sh` immediately.

Examples of acceptable native concepts if pressure proves them necessary:
- is-terminal / terminal capabilities;
- input mode state;
- output mode state;
- window dimensions;
- foreground/session relationships only if genuinely required.

Do NOT put Linux ioctl numbers into Morphic core types.
Do NOT return fake success for arbitrary ioctl calls merely to get a prompt.
An unsupported ioctl tolerated by BusyBox is not a blocker and should remain
unsupported.

MANDATORY OPENING REPAIR 1 — F_DUPFD INVALID MINIMUM MUST RETURN EINVAL
======================================================================

Current Linux/RV64 F_DUPFD handling performs lowest-free-at-or-above selection
and maps failure to EMFILE.

That incorrectly combines two different cases:

A. an invalid/impossible requested minimum;
B. a valid requested minimum for which no eligible descriptor is free.

At the Linux/RV64 compatibility edge, repair the distinction.

Required behavior for the current bounded descriptor model:

- an invalid/impossible F_DUPFD minimum must return EINVAL;
- a valid minimum with no free descriptor at or above it must return EMFILE;
- an invalid source descriptor remains EBADF;
- a valid successful request still returns the lowest free descriptor >= the
  requested minimum;
- successful duplication retains the SAME open resource description;
- reference ownership is incremented exactly once;
- failure leaves binding topology and resource reference counts unchanged.

A negative Linux minimum may arrive sign-extended in the RV64 argument register.
Validate the Linux argument before the bounded lowest-free search so such values
cannot be mistaken for ordinary exhaustion.

Keep Linux errno policy at the compatibility edge. Do not teach the neutral
BindingTable Linux errno meanings.

Focused regression coverage must prove at minimum:

1. invalid/impossible minimum -> EINVAL at the Linux/RV64 edge;
2. valid minimum with no eligible slot -> EMFILE;
3. invalid source descriptor -> EBADF;
4. valid minimum selects lowest eligible free descriptor;
5. failed cases preserve resource references and bindings;
6. successful aliases still share resource-owned offset/state and close
   lifecycle.

Do not hide the distinction by increasing descriptor capacity.

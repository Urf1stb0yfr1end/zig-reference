MISSION

Batch 25B is complete. The repository now has a real Linux/RV64 syscall boundary over a Linux-independent Morphic semantic seam plus a bounded generational resource substrate. Linux fd integers are process-visible compatibility identities; the permanent Morphic resource identity is generation-bearing and reusable by future non-Linux personalities.

Batch 26 must use that foundation to cross the next major ecosystem threshold in ONE campaign:

    isolated ELF/syscall proof
              ↓
    real file-backed resources
              ↓
    real pathname/openat pressure
              ↓
    real memory-management pressure
              ↓
    real exec replacement
              ↓
    real PT_INTERP/dynamic-ELF handoff pressure
              ↓
    an execution environment capable of supporting the next musl/BusyBox/Alpine inheritance campaigns

The goal is NOT to count Linux syscalls.
The goal is NOT to implement a complete POSIX filesystem.
The goal is NOT to duplicate Linux internals inside Morphic.

The goal is to implement the smallest coherent permanent mechanisms that unlock the largest next slice of the existing software world.

The Batch 26 planning rule is:

    smallest permanent mechanism
              ↓
    largest inherited software surface

or, in project vocabulary:

    MINIMUM IMPLEMENTATION SURFACE
    MAXIMUM CAPABILITY / INHERITANCE SURFACE
    MAXIMUM WHOLE-SYSTEM MENTAL MODEL

======================================================================
GATE A — FILE / DIRECTORY RESOURCE WORLD
======================================================================

Goal:

    pathname + directory context
          ↓
    filesystem object lookup
          ↓
    Morphic file/directory resource
          ↓
    project 57 ResourceRef
          ↓
    Linux fd binding
          ↓
    existing read/write/lifecycle machinery

Create only the smallest reusable filesystem substrate required by the proof.

Required permanent concepts should be Linux-independent where possible, for example:

- directory/root capability or object;
- file object/resource;
- bounded name/path traversal;
- file byte content / file length;
- current/open-file offset ONLY if real lseek/read pressure requires it, with the distinction between descriptor binding and underlying open-file state represented truthfully;
- directory enumeration only if required by the selected pressure fixture;
- metadata sufficient for the chosen Linux-facing proof;
- deterministic bounded storage for the proof filesystem;
- explicit errors independent of Linux errno.

Linux owns compatibility semantics such as:

- `AT_FDCWD` if implemented;
- Linux `openat` flags;
- Linux fd allocation;
- negative errno encoding;
- Linux pathname edge rules required by the bounded proof;
- Linux stat structure layout if implemented;
- Linux syscall numbers/register decoding.

Do not freeze the future QuirkM public filesystem API.
Do not implement a complete Unix inode/VFS architecture unless the evidence proves it is the smallest reusable mechanism.

Minimum machine proof for Gate A:

- a real RV64 userspace ELF issues a real Linux open/openat-class request against a deterministic filesystem fixture;
- success returns a real process-local Linux fd bound to a generation-bearing ResourceRef;
- read through that fd returns exact file bytes through the existing bounded user-memory path;
- close releases the binding/resource lifetime correctly;
- opening a missing path returns the correct Linux compatibility failure;
- an invalid userspace pathname pointer/range returns EFAULT without creating a resource/fd or mutating filesystem state;
- a file resource can reuse a resource-table slot at a later generation without breaking semantic I/O;
- if write/create/truncate behavior is implemented, every claimed mutation has failure-atomic evidence.

Strongly preferred additional pressure if it fits coherently:

- lseek with shared/open-file offset semantics represented at the right layer;
- minimal stat/fstat metadata;
- bounded directory iteration/getdents-style proof;
- root-relative path traversal rather than ambient ad-hoc string lookup.

The goal is a permanent file-resource mechanism that future Linux, QuirkM, Wasm, loaders, package tools, and VMM tooling can reuse.

======================================================================
GATE B — MEMORY MAPPING WORLD
======================================================================

Goal:

    process virtual-memory request
          ↓
    Linux mmap/brk compatibility adapter
          ↓
    Linux-independent mapping / memory-region operation
          ↓
    existing page ownership + Sv39 machinery

Search and compose existing memory-region, physical-page, address, range, page-table, and mapping modules before inventing a new subsystem.

Required pressure:

- anonymous writable user mapping;
- unmap;
- protection change where required;
- deterministic bounded address selection policy for the proof;
- preservation of W+X=0;
- mapping failure leaves prior mappings unchanged where atomicity is claimed;
- user access through the new mapping is mechanically proved.

Linux-facing minimum should be driven by the next inheritance thresholds, likely including the smallest credible subset of:

- `mmap`;
- `munmap`;
- `mprotect`;
- `brk` only if required by the chosen executable/runtime pressure.

File-backed mapping should be implemented in this campaign if it is necessary to reach Gate D or if it composes cleanly with Gate A without speculative complexity.

Do not emulate Linux internal vm_area_struct design simply because Linux has it.
The permanent Morphic concepts are memory object / mapping / permissions / ownership / address range, not Linux kernel implementation details.

Required proof:

- real U-mode code obtains/maps writable memory through the Linux adapter;
- writes/reads exact bytes;
- invalid/unmapped access is rejected according to the established trap policy;
- mprotect-like transition changes permissions as claimed;
- unmap removes accessibility;
- W+X remains zero;
- two QEMU runs agree on the evidence relevant to the deterministic proof.

======================================================================
GATE C — EXEC REPLACEMENT WORLD
======================================================================

Goal:

    running Linux process
          ↓
    pathname to executable
          ↓
    existing ELF planner
          ↓
    new process image construction
          ↓
    new Linux initial stack
          ↓
    enter new e_entry

Implement the smallest correct `execve`-class path necessary to replace the current process image with another real RV64 ELF obtained through the filesystem substrate.

Reuse:

- project 54 ELF load planning;
- project 55 Linux initial-stack planning;
- existing page-permission and user-entry machinery;
- project 57 resource identity;
- existing transfer and checked-range primitives.

Do not fork/clone a new process in this gate. Exec replacement is enough.

Required semantics/proof:

- executable bytes come from the filesystem path, not a compile-time special case wired directly into the kernel;
- argv/envp are validated from the old image before destructive replacement;
- new image construction is failure-atomic to the strongest practical bounded point: invalid ELF/path/arguments must not leave a half-replaced process image;
- successful exec replaces mappings according to the documented bounded policy;
- selected descriptor inheritance behavior is explicitly documented; do not accidentally invent CLOEXEC support unless implemented and proved;
- the new program receives a correct Linux-style initial stack through project 55;
- execution reaches the new ELF `e_entry` in U-mode;
- the new program performs at least one returning syscall through the existing Batch 25A/25B path and then terminates with a mechanically checked result.

A successful Gate C should prove a shell-like future is structurally plausible:

    program A
       ↓ execve
    program B

without yet claiming fork, clone, shell job control, signals, pipes, or BusyBox shell compatibility.

======================================================================
GATE D — PT_INTERP / DYNAMIC-ELF HANDOFF WORLD
======================================================================

This is the highest-leverage part of Batch 26 because dynamic ELF handoff is the bridge toward ordinary libc-linked software.

The kernel does NOT need to become a userspace dynamic linker.

Required architectural shape:

    executable ELF contains PT_INTERP
              ↓
    kernel locates interpreter path through Gate A filesystem
              ↓
    kernel maps executable + interpreter using reusable mapping/ELF machinery
              ↓
    Linux startup auxv/entry state identifies executable/interpreter facts correctly for the bounded proof
              ↓
    control enters interpreter entry
              ↓
    userspace interpreter is responsible for relocations/linking

Do not implement ELF relocations in the kernel merely to make a dynamic test pass.
Do not bake a specific musl path into Morphic architecture.
Linux pathname/PT_INTERP semantics belong to the Linux execution personality.

Minimum acceptable proof:

- parse a real or deliberately minimal RV64 ELF containing PT_INTERP;
- resolve the interpreter path through the real bounded filesystem mechanism;
- load/map both the main executable and interpreter through existing/reusable ELF/mapping machinery;
- enter the interpreter entry, not the main executable entry directly;
- provide enough initial-stack/auxv truth for the chosen interpreter fixture to independently verify main-program and interpreter placement/identity;
- the interpreter fixture transfers control or otherwise proves the required handoff relationship mechanically;
- mutations to PT_INTERP path, interpreter mapping, auxv values, or selected entry relationship cause the verifier to fail.

STRONG OPTIONAL SUCCESSOR PRESSURE:

If the environment can produce or contains a tiny real RV64 musl-linked dynamic executable/interpreter pair without introducing a large external dependency, use it as additional pressure. Do not fabricate a claim that full musl works if the proof is only a controlled PT_INTERP handoff.

======================================================================
LINUX/RV64 ADAPTER
======================================================================

The adapter must have two directions.

DECODE from saved user register state into either a supported semantic request or unsupported-syscall result.

At minimum support:

- write(64);
- exit(93);
- exit_group(94), sharing the current single-thread terminal semantic where truthful;
- unknown syscall -> ENOSYS.

ENCODE semantic completion/failure into Linux/RV64 user-visible results.

At minimum:

- successful write => a0 = exact byte count;
- invalid descriptor/resource => a0 = -EBADF;
- invalid/unmapped user range => a0 = -EFAULT;
- unsupported syscall => a0 = -ENOSYS;
- returning syscall => advance user sepc by exactly one 32-bit ECALL instruction and resume U-mode;
- terminal exit => do not resume after that ECALL.

Linux errno encoding belongs in the adapter, not the semantic executor.

Do not silently return zero for unsupported operations.
Do not collapse all failures to one errno.
Do not invent Linux semantics beyond what is implemented.

======================================================================
WRITE SEMANTICS
======================================================================

Linux descriptors 1 and 2 resolve to deterministic writable console/output resources through the explicit bootstrap resolver. Other descriptors fail with EBADF.

`write(fd, user_ptr, count)` must use existing bounded user-memory machinery.

Validate the ENTIRE requested readable user range before emitting any externally visible bytes.

Required behavior:

- count 0 succeeds with return 0 after descriptor check, without dereferencing user memory;
- valid readable mapped range emits exactly requested bytes and returns exactly count;
- invalid/unmapped/non-readable range returns EFAULT and emits no bytes;
- invalid fd returns EBADF and emits no bytes;
- no supervisor direct dereference of an untrusted user virtual pointer;
- no hidden SUM relaxation;
- reuse project 53/current copy machinery rather than another address walker.

If the transfer planner has bounded segment capacity, choose a sufficient current bound and report it honestly. Do not claim arbitrary Linux write length support.

Do not add partial-write semantics unless a real backend requires them here.

======================================================================
EXIT / EXIT_GROUP SEMANTICS
======================================================================

The semantic operation is termination of the currently executing bounded process-like U-mode instance with supplied status.

`exit` and `exit_group` may currently map to the same semantic terminal operation because there is no thread group yet.

The report must explicitly state that both Linux syscall numbers are decoded, there is no general thread-group/process model yet, their current terminal effect is intentionally identical, and complete Linux exit_group semantics are NOT claimed.

At least one of exit/exit_group must execute through real U-mode QEMU. The other must have deterministic adapter/executor coverage at minimum; exercise both in QEMU if cleanly possible without fake machinery.

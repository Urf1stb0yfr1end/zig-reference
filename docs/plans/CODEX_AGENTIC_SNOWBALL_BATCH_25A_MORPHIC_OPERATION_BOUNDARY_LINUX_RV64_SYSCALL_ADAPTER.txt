MISSION

Batch 24B proved that Alpz can load a real RV64 ELF, materialize the exact project-55 Linux-style initial process stack into real U RW/NX memory, enter at planner-derived e_entry with planner-derived SP, have U-mode independently parse argc/argv/envp/auxv, and return through the trusted ECALL boundary under strict two-QEMU evidence.

Batch 25A must turn that one terminal ECALL proof into the first real Linux/RV64 syscall boundary WITHOUT allowing Linux register numbers, syscall numbers, errno values, or file-descriptor conventions to become the internal architecture of Morphic.

Prove exactly this new architectural fact:

    a real RV64 Linux userspace ELF
              ↓
    Linux syscall register decoder
              ↓
    Linux-independent Morphic semantic operation request
              ↓
    bounded kernel operation execution
              ↓
    Linux result / negative-errno encoder
              ↓
    resume U-mode for returning operations
              ↓
    terminate only for terminal operation
              ↓
    strict external proof + second QEMU run

The first compatibility personality is Linux/RV64.
The reusable semantic operation boundary must not itself know Linux syscall numbers, RISC-V register names, or Linux errno numbers.

This batch is deliberately the first inheritance seam for later:

- Linux fd/resource work;
- Morphic native userspace;
- an early WebAssembly host/runtime consumer;
- pipes/sockets/timers/devices through shared resources;
- later hypervisor-control operations where the semantics genuinely fit.

Do NOT freeze a public Morphic native ABI in this batch.
Do NOT implement WebAssembly in this batch.
Do NOT build a general FD/resource table yet; that is the immediate next pressure.
Do NOT begin VFS, mmap, execve, fork/clone, signals, futexes, sockets, or dynamic linking.

The goal is maximum inherited semantics per unit of new privileged complexity, while still moving directly toward real Linux/BusyBox compatibility.

SEMANTIC MORPHIC OPERATION BOUNDARY

Create or reuse the smallest architecture-neutral semantic boundary that can express this batch without importing Linux ABI identity.

Required semantic concepts:

1. WRITE BYTES TO A RESOURCE-LIKE DESTINATION

Conceptually:

    write_bytes {
        destination/resource identity,
        user guest address,
        byte count
    }

2. TERMINATE CURRENT PROCESS-LIKE EXECUTION

Conceptually:

    terminate {
        status
    }

3. COMPLETION

Conceptually distinguish:

    success(value/count)
    semantic failure
    terminal completion(status)

The exact Zig API is implementation work and must follow current repository conventions.

The semantic types MUST NOT contain:

- Linux syscall numbers;
- `__NR_*` names;
- Linux errno numbers;
- RISC-V register names such as a0/a7;
- raw trap-frame layout;
- Linux fd table ownership semantics that do not exist yet.

RESOURCE IDENTITY — KEEP IT NARROW

Batch 25A needs enough resource identity to prove write without prematurely designing the entire resource model.

A preferred shape is an opaque/typed resource identity at the semantic layer, with a proof-only bootstrap resolver mapping Linux descriptors 1 and 2 to writable console resources.

If current typed-handle machinery fits cleanly, reuse it.

Do NOT claim this bootstrap resolver is a general process FD table.
Do NOT claim generation, duplication, inheritance, rights restriction, close-on-exec, transfer, or lifetime semantics unless actually implemented and proved.

Batch 25B should be able to replace the bootstrap resolver with a real bounded per-process resource/FD table WITHOUT changing the Linux syscall register decoder and WITHOUT forcing Linux errno/syscall numbers into the semantic operation executor.

That replacement property is a major acceptance criterion.

LINUX/RV64 ADAPTER

The Linux/RV64 adapter must have two directions:

A. DECODE

From saved user register state, derive a supported semantic request or unsupported-syscall result.

At minimum support:

- write(64)
- exit(93)
- exit_group(94) through the same current single-thread termination semantic where truthful
- unknown syscall -> ENOSYS

B. ENCODE

Translate semantic completion/failure back into Linux/RV64 user-visible results.

At minimum:

- successful write => a0 = exact byte count;
- invalid descriptor/resource => a0 = -EBADF;
- invalid/unmapped user range => a0 = -EFAULT;
- unsupported syscall => a0 = -ENOSYS;
- returning syscall => advance user sepc by exactly one 32-bit ECALL instruction and resume U-mode;
- terminal exit => do not resume after that ECALL.

Linux errno encoding belongs in this adapter, not in the semantic executor.

Do not silently return zero for unsupported operations.
Do not collapse all failures to one errno.
Do not invent Linux semantics beyond what is actually implemented.

WRITE SEMANTICS

For this batch, Linux descriptors 1 and 2 must resolve to deterministic writable console/output resources through the explicit bootstrap resolver.

Other descriptors must fail with EBADF.

`write(fd, user_ptr, count)` must use the existing bounded user-memory machinery.

Critical rule:

Validate the ENTIRE requested readable user range before emitting any externally visible bytes.

The failure path must not print a prefix and then discover an invalid later page.

Required behavior:

- count 0 succeeds with return 0 after the descriptor check, without dereferencing user memory;
- a valid readable mapped range emits exactly the requested bytes and returns exactly count;
- invalid/unmapped/non-readable range returns EFAULT and emits no bytes;
- invalid fd returns EBADF and emits no bytes;
- no supervisor direct dereference of an untrusted user virtual pointer;
- no hidden SUM relaxation;
- use project 53/current copy machinery rather than another address walker.

If the current transfer planner requires a bounded segment capacity, choose a capacity sufficient for the currently proved process address-space shape and report the bound honestly. Do not call it arbitrary Linux write length support.

Do not introduce partial-write semantics unless a real output backend requires them in this batch. If the proof backend is deterministic and all-or-nothing, claim only that bounded behavior.

EXIT / EXIT_GROUP SEMANTICS

The semantic operation is termination of the currently executing bounded process-like U-mode instance with a supplied status.

`exit` and `exit_group` may map to the same semantic terminal operation at this single-thread boundary because there is no thread group yet.

The report must explicitly say:

- both Linux syscall numbers are decoded;
- the current machine has no general thread-group/process model;
- therefore their current observable terminal effect is intentionally identical;
- this does NOT claim complete Linux exit_group semantics.

At least one of exit/exit_group must be exercised through real U-mode QEMU execution. The other must have deterministic adapter/executor test coverage at minimum. If it can be real-QEMU exercised cleanly without duplicating the whole fixture or creating fake process machinery, do so; otherwise preserve the narrower evidence distinction.

REAL RV64 USERSPACE FIXTURE

Add a separately built RV64 ELF dedicated to Batch 25A, preferably inheriting the Batch 24B two-segment R-X + RW-/BSS shape and exact startup-stack entry.

The fixture should use raw ECALLs and no libc/runtime/startup object.

It must prove a returning-syscall sequence before terminal exit.

A strong deterministic sequence is:

1. preserve/validate enough Batch 24B startup truth to establish the same process-start inheritance;
2. issue one deliberately unsupported syscall number and require a0 == -ENOSYS;
3. write a frozen message from real user memory to fd 1 and require a0 == message length;
4. attempt write with an invalid fd and require -EBADF with no output;
5. attempt write from a deliberately invalid/unmapped user range and require -EFAULT with no output;
6. optionally write a second frozen marker to fd 2 and require exact byte count;
7. terminate with a frozen status through real Linux exit or exit_group;
8. execution after the terminal ECALL must be an impossible/failure path.

Use unique artifact-derived ECALL PCs and deterministic message bytes.

Do not let the fixture read kernel success flags.
The fixture must judge return values from its own architectural a0 state.

RETURN-PATH PROOF

Batch 24B treated the successful ECALL as terminal. Batch 25A must prove the stronger repeated boundary:

    U-mode
      ↓ ECALL
    S-mode trap
      ↓ decode/execute/encode
    sepc += 4
      ↓ SRET
    same U-mode ELF continues
      ↓ another ECALL
    ...
      ↓ terminal exit ECALL
    S-mode terminal handoff

For every returning syscall prove at minimum:

- scause = U-mode ECALL;
- SPP indicates U-origin;
- trap PC equals the expected artifact ECALL PC;
- resumed PC equals trap PC + 4;
- expected SP remains the planner-derived initial/process stack state unless the fixture intentionally adjusts it;
- no unintended page-table/resource allocation change;
- no W+X mapping;
- relevant code/data/stack PTE truth remains unchanged;
- Linux return value is exact.

Do not rely only on a final success marker; record the ordered syscall evidence.

2. MATERIALIZE ALL VALIDATED PT_LOAD CONTENT, NOT JUST ITEMS()[0]
======================================================================

The materializer must consume the complete validated load plan required by the
external image.

Do not simply replace:

    items()[0]

with:

    items()[0]
    items()[1]

or another artifact-specific fixed count.

Iterate the actual planned segment set within explicit bounds.

For every segment required by the load plan:

- copy every file-backed byte from the exact executable artifact;
- zero every required p_memsz - p_filesz byte;

======================================================================
3. HANDLE PAGE GEOMETRY CORRECTLY
======================================================================

Real ELF segments are not guaranteed to fit one page or to begin/end on page
boundaries.

The implementation must reason correctly about:

    segment virtual start/end
    file start/end
    page-aligned virtual coverage
    offset of segment bytes inside first page
    final partial page
    BSS / zero-fill range
    segment alignment relation already validated by project 54

Do not assume:

    p_vaddr % 4096 == 0
    p_offset % 4096 == 0
    p_filesz == p_memsz
    one segment == one page

Use checked arithmetic for all align-up, align-down, page-count, and offset
calculations.

If page-rounded coverage from two valid adjacent segments aliases the same
physical user page, do not blindly attempt two independent mapPage operations.

Inspect the exact external artifacts and implement the smallest correct general
composition for shared-page contributions if real pressure requires it.

Do not invent broad ELF semantics that the current artifact does not require,
but do not corrupt valid bytes merely because segment boundaries are not page
boundaries.

======================================================================
4. FILE BYTES, BSS, AND UNTOUCHED PAGE BYTES
======================================================================

Materialized memory must derive from the exact external ELF bytes.

For each segment:

    file-backed portion
        -> copied exactly

    p_memsz - p_filesz
        -> zero

For fresh pages, bytes not supplied by any file-backed segment contribution must
begin deterministically zero unless a deliberately shared-page rule requires
preserving a contribution from another segment.

Do not leak stale physical-frame contents into userspace.

The page allocator / backing owner must maintain the repository's existing
zeroing and ownership guarantees.

======================================================================
5. FINAL PAGE PERMISSIONS
======================================================================

A user executable image should enter userspace with final intended permissions,
not with a convenience RWX window.

Prefer the safe flow:

    allocate supervisor-owned physical backing
        ->
    populate through supervisor physical access
        ->
    install user mappings with FINAL permissions
        ->
    sfence.vma as required
        ->
    fence.i before executing newly materialized code

Do not map every image page user-RWX merely to simplify copying.

W+X remains prohibited unless repository architecture explicitly changes with
new evidence; this task does not justify such a change.

For page-level permission composition where multiple segment contributions touch
the same page, derive the smallest correct final permission policy from the
validated artifact and real pressure. Do not silently widen permissions.

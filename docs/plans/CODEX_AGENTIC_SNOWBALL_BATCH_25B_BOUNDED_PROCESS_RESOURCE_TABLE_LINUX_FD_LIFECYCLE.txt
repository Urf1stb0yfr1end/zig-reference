MISSION

Batch 25A proved the first real Linux/RV64 syscall boundary while establishing the architectural inheritance seam:

    real RV64 Linux userspace ELF
              ↓
    thin Linux/RV64 syscall adapter
              ↓
    Linux-independent Morphic semantic operation request
              ↓
    bounded kernel execution
              ↓
    semantic completion/failure/termination
              ↓
    Linux result / negative-errno adapter
              ↓
    exact U→S→U return or terminal handoff

That boundary must now become economically useful.

Batch 25B must replace the proof-only stdout/stderr resolver with the first bounded per-process resource table and first real Linux file-descriptor lifecycle, while preserving the Batch 25A law that Linux descriptor numbers and Linux errno values are compatibility-edge identities rather than Morphic internal architecture.

Prove exactly this new architectural fact:

    Linux fd integer
          ↓
    Linux per-process fd adapter/table view
          ↓
    Morphic resource reference / resource-table entry
          ↓
    shared semantic resource operation
          ↓
    bounded resource backend
          ↓
    semantic completion/failure
          ↓
    Linux result / errno encoding

and prove that the same underlying Morphic resource-table mechanism is suitable, without Linux identity, for later:

- QuirkM native typed handles;
- WebAssembly host resources;
- pipes, sockets, timers, shared memory, devices, files, and process-like resources;
- compatibility providers and agent-visible capability composition;
- later hypervisor-control resources where the semantics genuinely fit.

The immediate compatibility target is Linux/RV64.
The permanent architecture target is a reusable resource substrate.

Batch 25B is PASS only if Linux compatibility becomes materially stronger AND the reusable Morphic seam becomes stronger at the same time.

======================================================================
RESOURCE-TABLE MODEL — MINIMUM REQUIRED SEMANTICS
======================================================================

The exact Zig API is not frozen here. Codex must choose the smallest API consistent with current repository conventions and actual reuse.

At minimum the reusable layer must distinguish:

- an empty slot from a live resource binding;
- one process-local descriptor binding from the underlying resource identity/reference;
- release of a binding from destruction of an underlying resource when aliases still exist, if aliasing is proved in this batch;
- live resource from stale/invalid resource reference if generational safety is adopted;
- resource operation availability sufficiently to reject reading from a write-only proof resource or writing to a read-only proof resource if Batch 25B exposes distinct stdin/stdout/stderr directions.

Do NOT force a complete future rights system into this batch unless current existing modules make it essentially free and the proof uses it.

A plausible internal shape, NOT a mandated public API, is:

    ProcessResourceTable
        descriptor bindings / local slots
            ↓
        opaque Morphic ResourceRef
            ↓
        bounded backing resource entries
            ↓
        backend capability/kind

or, if current repository modules support it more cleanly:

    LinuxFdTable
        fd → ResourceHandle

    ResourceTable
        generational ResourceHandle → resource entry/backend identity

The crucial property is separation, not exact type names.

Do not conflate:

- Linux descriptor number;
- descriptor-table slot identity;
- resource handle/reference;
- backing object identity;
- device/backend implementation.

If Batch 25B can truthfully use a single table with a clear abstraction boundary, do so. Do not create layers only for diagram aesthetics.

STDIN / STDOUT / STDERR BOOTSTRAP
======================================================================

The initial process must now receive real descriptor bindings through the process resource/FD table rather than a syscall-local special case.

At minimum:

- fd 0 → bounded deterministic readable stdin-like resource;
- fd 1 → bounded deterministic writable stdout-like resource;
- fd 2 → bounded deterministic writable stderr-like resource.

These are bootstrap resources for the proof, not a complete TTY implementation.

Preferred stdin proof backend:

- frozen deterministic byte payload known to the external verifier;
- bounded cursor/read behavior only as far as actually implemented;
- no hidden dependence on host terminal timing/input;
- explicit EOF behavior if reached;
- if read semantics are all-or-nothing for this bounded proof, say so;
- do not claim general terminal line discipline, blocking, signals, canonical mode, pipes, or asynchronous input.

stdout/stderr may continue using deterministic proof output, but descriptor resolution must occur through the real table.

======================================================================
READ SEMANTICS
======================================================================

Add the smallest truthful Linux `read` behavior that exercises the resource table and project 53-style user transfer safety.

Required properties:

- valid readable descriptor + valid writable U range → bytes copied to U memory and exact count returned;
- invalid/closed descriptor → `-EBADF`, no U-memory mutation;
- descriptor not readable under implemented proof capability → Linux-visible failure chosen from verified primary ABI semantics; do not invent an errno from memory;
- invalid/unmapped/non-writable U destination → `-EFAULT`, no partial user-memory mutation for an all-or-nothing proof backend;
- count 0 follows verified Linux edge semantics for descriptor validation and memory dereference behavior; encode exactly what is implemented and tested;
- EOF behavior deterministic and externally proved if input can be exhausted;
- no supervisor direct dereference of arbitrary U virtual addresses;
- reuse current bounded user-copy/page-table machinery;
- no SUM relaxation merely to make copy-out convenient.

Whole-range validation must occur before externally visible state is consumed if the backend claims failure atomicity.

If stdin has a cursor, an EFAULT must not consume input bytes before the operation is known to succeed.

That rollback/non-consumption property is important and should be mutation-tested/evidenced.

======================================================================
WRITE SEMANTICS THROUGH THE REAL TABLE
======================================================================

Preserve Batch 25A write truth, but remove proof-only fd resolution from the syscall handler/backend.

Required:

- fd lookup through process-local table;
- stdout and stderr both resolve through table entries;
- valid writable resource + valid U source → exact bytes/count;
- invalid/closed fd → `-EBADF`, no output;
- unreadable/unmapped U source → `-EFAULT`, no output;
- whole requested readable range validated before visible output under current all-or-nothing proof semantics;
- zero-length behavior verified and tested;
- no new direct page-table walker;
- no claim of general Linux partial-write behavior unless actually implemented.

======================================================================
CLOSE SEMANTICS
======================================================================

Prove real descriptor lifetime.

At minimum:

1. a live descriptor succeeds for its supported operation;
2. `close(fd)` succeeds once;
3. subsequent operation using that fd returns `-EBADF`;
4. second close of the same now-invalid fd returns `-EBADF`;
5. closing one descriptor alias must not invalidate another surviving alias to the same underlying resource where duplication has been performed;
6. resource-table evidence must show the correct lifetime transition without leaking Linux errno into the reusable layer.

Do not claim:

- close-on-exec;
- multithreaded close races;
- file-description offset semantics;
- asynchronous close completion;
- device flush semantics;
- socket shutdown;
- general POSIX lifetime semantics

unless specifically implemented and proved.

======================================================================
DUPLICATION / ALIASING SEMANTICS
======================================================================

This batch should prove at least one descriptor duplication path because it is the first pressure that forces a useful distinction between a descriptor binding and an underlying resource.

Choose the smallest Linux interface whose ABI semantics can be implemented truthfully and verified from primary sources.

Preferred if simple in the current ABI: `dup`.
If RV64 generic Linux exposes a more convenient path through `fcntl(F_DUPFD...)` or if `dup3` is materially easier without overclaiming flags, Codex may choose it, but document the decision.

Minimum proof:

- duplicate a valid descriptor;
- returned descriptor is a distinct Linux-visible descriptor number;
- both descriptors name the same underlying resource/open state for the semantics currently represented;
- close one alias;
- other alias remains usable;
- closed alias is `-EBADF`;
- deterministic allocation chooses the expected lowest/eligible slot according to the selected Linux interface’s verified rule;
- invalid source descriptor fails correctly;
- table-full behavior is bounded, deterministic, and mapped to a verified Linux errno only at the adapter edge.

Do not fake full Linux open-file-description semantics if the backing proof resources have no offset/status state yet.
State narrowly what “same underlying resource” means in this implementation.

======================================================================
STALE REFERENCE / GENERATIONAL SAFETY
======================================================================

The repository already has generational-handle knowledge. Query it before deciding how resource references should reject stale identities.

If it composes cleanly, prefer stale-safe resource references so a released internal resource slot cannot silently become a different resource when reused.

If introducing generation tracking would require disproportionate unrelated architecture in this batch, preserve the seam and defer it explicitly rather than implementing a half-correct generation model.

Important distinction:

Linux fd reuse after close is compatibility behavior and is allowed.
A stale internal Morphic resource reference silently becoming a different underlying object should be avoided if the existing reusable machinery can prevent it cheaply.

This is a concrete example of QuirkM/Linux separation:

    Linux personality:
        reusable integer fd semantics preserved

    Morphic/QuirkM direction:
        stale-safe typed/generational resource reference

If implemented, prove both truths separately.

REAL RV64 USERSPACE FIXTURE
======================================================================

Use a separately built real RV64 ET_EXEC fixture with raw ECALLs and no libc/runtime.

Inherit the Batch 25A two-segment/startup shape unless current implementation pressure requires a narrowly justified change.

A strong ordered sequence is:

1. preserve enough Batch 24B/25A startup truth to prove same real process entry;
2. unknown syscall → require `-ENOSYS`;
3. read from fd 0 into valid U buffer → require exact frozen bytes/count;
4. prove the read bytes in U memory, not merely a kernel log;
5. read with invalid U destination → require `-EFAULT` and prove stdin cursor/non-consumption unchanged;
6. write read bytes or a frozen message through fd 1 → exact output/count;
7. duplicate fd 1 using selected Linux interface → require deterministic new descriptor;
8. write through duplicate → exact output/count;
9. close original fd 1 → success;
10. write through original fd 1 → `-EBADF`, no output;
11. write through duplicate → still succeeds;
12. close duplicate → success;
13. second close / use-after-close → `-EBADF`;
14. optional stderr proof through fd 2 if it materially strengthens table bootstrap evidence;
15. terminal exit/exit_group with frozen status;
16. impossible post-exit path.

Codex may reorder or slightly refine this sequence to fit exact fixture constraints, but the proof must include read, real table lookup, duplicate aliasing, close lifetime, surviving alias, invalid/closed rejection, and terminal handoff.

Unique artifact-derived ECALL PCs must remain externally verifiable.

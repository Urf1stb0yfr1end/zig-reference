GATE A — REAL OPENAT / FILE RESOURCE PATH
======================================================================

Make the actual RV64 Linux `openat` ECALL cause the file operation.

Required flow:

    U-mode openat ECALL
        -> decode actual RV64 syscall arguments
        -> validate/copy pathname from userspace via accepted transfer machinery
        -> resolve root/directory context
        -> project 58 lookup
        -> create/reuse the minimum real open-file state required by the proof
        -> project 57 generation-bearing ResourceRef
        -> process-local Linux fd binding
        -> Linux-facing result / errno translation
        -> return through exact sepc + 4

Required proof cases:

- successful `/etc/message` open;
- file bytes subsequently read through the real descriptor/resource path, not from a supervisor-side pre-read;
- missing pathname -> Linux ENOENT;
- invalid userspace pointer/range -> Linux EFAULT;
- failed copy/lookup must not leave partial descriptor/resource mutation;
- resource generation/lifetime remains correct;
- inherited Batch 25B generation semantics remain intact.

Use actual syscall arguments. A changed pathname or invalid pointer must change behavior for the correct reason.

Do not build a general VFS if this proof does not require it.

======================================================================
GATE B — REAL MMAP / MPROTECT / MUNMAP
======================================================================

Make the actual ECALLs cause live machine translation changes.

Required `mmap` path:

    U-mode mmap ECALL
        -> decode/validate args
        -> project 59 candidate/policy validation as useful
        -> allocate/select owned physical frame(s)
        -> live Sv39 map commit
        -> required sfence.vma / fence sequencing
        -> return actual mapped VA

Required proof:

- mapping does not exist before the syscall;
- mmap creates the real user mapping;
- userspace writes/reads through it successfully;
- returned address corresponds to the actual mapping.

Required `mprotect` path:

    U-mode mprotect ECALL
        -> validate target/range/protection
        -> update project 59 state where appropriate
        -> live PTE permission replacement
        -> required invalidation
        -> return success only after the real transition

Then userspace must actually attempt a forbidden write.

The machine must trap for the expected reason. Record independently useful evidence including fault cause, fault VA/stval, fault PC, expected operation phase, and the mapping/PTE state needed to prove the fault was permission-driven rather than synthetic.

The kernel may deliberately recognize this expected proof fault and resume at a known continuation, but it must not fabricate a fault that never occurred.

Required `munmap` path:

    U-mode munmap ECALL
        -> validate target/range
        -> remove live PTE
        -> update ownership/candidate state coherently
        -> required invalidation
        -> return success

Then userspace must actually access the unmapped address and generate the expected real page fault.

Again, record enough machine facts for the verifier to distinguish a genuine missing translation from a printed claim.

Throughout Gate B:

- W+X remains zero;
- invalid ranges/overlaps fail without corruption;
- mapping ownership remains coherent;
- no pre-map/protect/unmap outside the ECALL path may substitute for the syscall-caused operation.

    Program A in U-mode

        -> project 54 ELF planning

        -> project 55 initial stack
        -> prepare replacement page-table/image state
        -> validate complete candidate
        -> atomic candidate-to-live commit
        -> destroy/replace expected old image mappings
        -> enter new image
        -> Program B genuinely executes in U-mode

Requirements:

- filesystem executable content is a real ELF, not a marker string;
- invalid pathname/argv/envp or malformed executable must fail without destroying Program A;
- descriptor/resource inheritance is explicit and generation-correct;
- successful execve does not return to Program A;
- Program B must produce independently distinguishable machine evidence;
- do not use `userServiceSupervisorResume` as a substitute for successful process-image replacement.

The verifier must be able to tell that Program A stopped and Program B executed, rather than merely trusting `program_b=...` text.

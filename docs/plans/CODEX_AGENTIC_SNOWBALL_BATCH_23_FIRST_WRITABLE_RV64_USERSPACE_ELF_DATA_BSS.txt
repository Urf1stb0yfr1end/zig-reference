STRICT SCOPE

Prefer the smallest architecture that proves writable ELF data and BSS truth.

The target fixture should be one tiny separately built RV64 ELF64 little-endian ET_EXEC containing exactly the required process-image shape:

- one R-X PT_LOAD containing executable guest code;
- one RW- PT_LOAD containing initialized data;
- writable p_memsz greater than writable p_filesz;
- therefore a non-zero BSS tail;
- one e_entry inside the executable PT_LOAD;
- no PT_INTERP;
- no dynamic linking;
- no runtime relocations;
- no TLS;
- no shared-library semantics;
- no initial Linux process-stack ABI;
- no libc;
- no Linux syscall ABI.

The deliberate ECALL remains a proof signal into the already-proven trusted supervisor path, not a Linux syscall.

Do not add general process objects, execve, VFS, mmap/brk, argv/envp/auxv, signals, futexes, threads, BusyBox, Alpine, QEMU hosting, KVM, or hardware virtualization.

REAL GUEST ELF ARTIFACT

The guest must remain a separately built real ELF artifact, distinct from the Alpz kernel ELF.

It must not be:

- a hand-authored instruction/data byte array inside the kernel;
- the historical probe with decorative ELF metadata;
- a copied slice of kernel text/data;
- an opaque runtime structure merely labeled as ELF.

Prefer source plus deterministic linker/build rules under existing fixture/build conventions.

The exact artifact inspected by the external verifier must be the artifact embedded or otherwise consumed by the kernel build. Make artifact divergence mechanically difficult.

The verifier must independently establish from the emitted artifact at least:

Do not trust only kernel-emitted text for ELF structure.

MACHINE MEMORY / MAPPING REQUIREMENT

Preserve the Batch 22B executable proof wherever truthful.

For the R-X segment:

- preserve exact planner-selected source-byte loading;
- preserve direct source-to-loaded byte comparison;
- preserve U R-X and not-writable mapping truth;
- execute FENCE.I after changing executable bytes and before entering them;
- do not emit SFENCE.VMA unless translation state actually changed.

For the RW- segment:

1. allocate or reuse bounded allocator-owned physical storage with explicit ownership/accounting;
2. establish an exact U RW/NX mapping covering the planned writable memory range;
3. copy exactly the planner-selected initialized file bytes;
4. directly compare every initialized source byte with its volatile loaded destination byte;
5. zero exactly the planner-declared BSS tail;
6. directly establish that the bounded BSS region under proof is zero before U-mode entry;
7. do not execute FENCE.I merely because non-executable data changed;
8. execute SFENCE.VMA only when required by a real translation change and report that fact precisely.

Never collapse p_memsz to p_filesz.
Never use a checksum as a substitute for exact byte comparison.
Never widen RW data to executable.
Never make an executable user mapping writable for loader convenience.
Never claim unchanged resource counts if a new data frame or page-table page was actually introduced.

Choose the smallest non-overlapping user virtual layout compatible with current HEAD. Reuse existing page-table levels when truthful, but do not contort the proof merely to preserve an old count.

U-MODE BEHAVIOR

The guest must make the new process-image facts observable through real execution.

Use a deliberately tiny deterministic sequence. At minimum the guest must:

- load a known initialized value from the RW PT_LOAD;
- establish that it equals the expected fixture constant;
- read a bounded location in the BSS tail and establish it is zero;
- write a distinctive Batch 23 value into writable mapped storage, preferably into the BSS location just proved zero;
- establish a small fixed set of unique Batch 23 register markers;
- issue the deliberate ECALL;
- fail-stop if execution unexpectedly resumes in a path that should not occur.

Do not introduce a general userspace runtime merely for the fixture.

SUPERVISOR RETURN PROOF

After the guest ECALL mechanically prove at least:

- trap cause is U-mode ECALL;
- trap status proves expected prior privilege;
- trap PC belongs to the independently reconstructed executable segment and has the expected relation to e_entry/guest instructions;
- expected Batch 23 register markers are present in the trusted trap frame;
- the initialized value used by the guest came from the ELF-loaded RW storage;
- the selected BSS location was zero before guest execution;
- the guest's distinctive write is visible after return in the same allocator-owned physical storage backing the RW user mapping;
- executable segment bytes remain unchanged;
- executable PTE is U R-X and not writable;
- writable PTE is U RW/NX;
- W+X leaf count remains zero;
- SATP/root truth remains coherent;
- allocator and page-table accounting matches deliberately introduced resources;
- no unrelated translation/permission drift occurred;
- supervisor continuation is reached.

CODEX AGENTIC SNOWBALL BATCH 10 — RISC-V EXECUTION PROBE

MISSION

Apply the first real cross-architecture execution pressure to the Morphic runtime.

Batch 09 proved one shared target-neutral Morphic core can execute through hosted and deterministic fake machine implementations on the development host while preserving byte-identical canonical observables.

Batch 10 must now answer a narrower and more important question:

DO THE SAME SETTLED SEMANTICS SURVIVE ACTUAL RISC-V EXECUTION WITHOUT BEING REWRITTEN?

The preferred first pressure target is a riscv64 Linux userspace executable run under QEMU user-mode, because it exercises real RISC-V machine code while avoiding premature privileged-mode, firmware, trap, device, and boot semantics.

The governing idea is:

ONE CORE.
SAME SCENARIO.
DIFFERENT ISA.
NO SECOND SEMANTIC IMPLEMENTATION.

This is an evidence-gathering batch, not a race toward Alpine.

Do not begin Linux boot handoff.
Do not begin supervisor-mode or machine-mode runtime code.
Do not begin SBI, CSRs, traps, interrupts, MMIO, UART, FDT, PLIC, CLINT, VirtIO, page-table activation, a hypervisor, or a universal HAL.
Do not add a RISC-V-specific copy of the Morphic runtime.
Do not create speculative architecture modules merely because a future freestanding backend might need them.
Do not add a private cross-target DSL or custom interface language.

If the existing hosted/core code can cross-compile and execute correctly with little or no new reusable capability, that is a successful Snowball result. Do not manufacture novelty to make the batch look larger.

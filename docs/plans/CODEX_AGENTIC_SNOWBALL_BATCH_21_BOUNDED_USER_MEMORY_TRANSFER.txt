MISSION

Advance the merged Batch 20 RISC-V machine boundary by exactly one architectural pressure on the shortest credible path toward Alpine:

prove a small, reusable, bounded user-memory transfer contract that can safely copy bytes from U-mode memory into trusted supervisor memory and safely copy trusted supervisor bytes back into U-mode memory, with explicit range validation, permission validation, failure behavior, and no unchecked supervisor dereference of a user virtual pointer.

Batch 20 proved:

U-mode
→ ECALL
→ trusted S-mode trap stack
→ fixed register-only supervisor service
→ SRET back to U-mode
→ resumed user execution
→ terminal U-mode ECALL
→ known S-mode continuation

Batch 21 must add:

U-mode owns bytes
→ user passes bounded pointer + length
→ supervisor validates the entire range
→ supervisor copies bytes IN safely
→ supervisor produces/records deterministic result
→ SRET back to U-mode
→ supervisor later copies bytes OUT safely
→ user observes the written bytes
→ invalid write range is rejected before mutation
→ terminal U-mode ECALL
→ known S-mode continuation

This is the first intentional user-pointer pressure.

It is still NOT a Linux syscall ABI.

Do not build a syscall table.
Do not assign Linux syscall numbers.
Do not add processes.
Do not add a userspace ELF loader in this batch.
Do not add VFS, file descriptors, mmap, brk, signals, futexes, threads, procfs, sockets, or Alpine rootfs work in this batch.

The point is to earn the safe user-memory primitive that the ELF loader, syscall layer, strings, argv/envp, file I/O, and later Linux ABI work will need repeatedly.


WHY THIS IS THE NEXT ALPINE STEP

Read:

docs/roadmaps/SELF_HOSTED_RECURSIVE_ABI_LAB.md

The repository is now deliberately optimizing for the shortest credible route to:

M0 native execution foundation
→ M1 BusyBox baseline
→ M2 musl/dynamic ELF
→ M3 useful Alpine
→ M4 QEMU/TCG self-hosting
→ recursive differential ABI testing

Do not optimize Batch 21 for feature breadth.

Optimize it for a primitive that removes future repeated work.

A Linux-compatible kernel cannot safely implement common syscalls, argv/envp loading, path strings, read/write buffers, ioctl payloads, socket addresses, or dynamic-loader interactions if user pointers are merely trusted or dereferenced casually.

Therefore this batch should make user-memory transfer a mechanically testable foundation now, before syscall breadth begins.

3. Batch 21 finishes before the canonical Morphic frame begins.
4. Batch 21 reuses the existing Batch 19/20 U RX code page and U RW/NX stack page.

6. Batch 21 allocates zero new page-table frames.

9. Exactly two leaves remain U=1.
10. W+X remains zero.

18. Copy-OUT requires U=1 and writable permission for every touched page.
19. The successful copy-IN transfers exactly the requested bytes to trusted supervisor-owned storage.

21. The supervisor produces a deterministic output payload in trusted memory.
22. The successful copy-OUT transfers exactly that payload into an allowed U RW range.
23. U-mode resumes and independently verifies the bytes written by the supervisor.
24. At least one permission-invalid copy-OUT attempt is rejected before any target byte is changed.
25. At least one unmapped/out-of-range/overflow rejection path is mechanically exercised without turning into an uncontrolled page fault.
26. Range rejection behavior is explicit and deterministic.
27. No partial write occurs on a prevalidation failure.
28. Trap entry continues to use the trusted supervisor-only trap stack before any trap-frame memory access.
29. Repeated returns to U-mode correctly rearm the trusted sscratch/trap-stack convention.
30. A final terminal U-mode ECALL returns deliberately to the known S-mode continuation.
31. stvec is restored and read back.
32. sscratch is neutralized and read back.
33. canonical 765-byte Morphic equality remains exact across hosted, fake, and both real machines.
34. aggregate repository validation passes.
35. documentation and recipe metadata describe only what is mechanically proved.
36. no Linux ABI or general syscall-copy semantics are falsely claimed.

SAFE ACCESS STRATEGY

Prefer keeping SUM=0 throughout Batch 21.

The strongest current design is to treat the user virtual pointer as data, not as a supervisor pointer:

user VA range
    ↓
checked arithmetic
    ↓
walk/query each page in active Sv39
    ↓
require U and required R/W permission
    ↓
resolve physical backing
    ↓
copy through supervisor-owned/identity-mapped physical access

This is preferable to simply setting SUM and dereferencing arbitrary user virtual addresses in S-mode because it makes the validation boundary explicit and keeps invalid user pointers from becoming uncontrolled supervisor faults.

Do not assume physical contiguity across user virtual pages.

A transfer plan must be able to split one logical user range into bounded physical segments.

Even if the real machine success path fits inside the existing one-page user stack, the reusable planner should have unit tests for:

- same-page ranges;
- page-boundary crossing;
- distinct noncontiguous physical pages;
- overflow;
- unmapped page;
- U=0 page;
- read permission rejection;
- write permission rejection;
- zero-length policy;
- maximum bounded segment count.

If the machine proof can cheaply exercise a real cross-page read without weakening the user-code execution mapping, do so. A good optional proof is a read-only range that crosses from the end of the U RX code page into the beginning of the U RW stack page, because both pages are readable while their physical frames need not be contiguous.

Do not force that optional geometry if it materially complicates the batch. The required machine milestone is safe real user-pointer transfer plus failure atomicity; cross-page correctness may be proved in the reusable module if the final QEMU case remains one-page.


REUSABLE PLANNER SHAPE

If repository discovery confirms this capability is missing, add one small bounded planning module.

It should NOT know about ECALL numbers, Linux, Alpine, processes, or the freestanding recipe.

It should accept:

- user virtual start address;
- byte length;
- requested access kind: read-from-user or write-to-user;
- a bounded resolver/query provider that can report mapping and permissions for each page.

It should return either:

- a bounded sequence of physical transfer segments;

or a deterministic error.

Each segment should contain enough information to perform a copy without trusting the original user pointer, for example:

- user page/range fragment;
- physical address;
- byte count;
- optional raw permission evidence if useful.

Required planner properties:

- checked start + length arithmetic;
- no wraparound;
- every touched byte represented exactly once;
- ordered segments;
- no overlap inside the plan;
- no omitted gap;
- page offset preserved;
- U=1 required;
- read permission required for copy-IN;
- write permission required for copy-OUT;
- deterministic segment bound;
- no heap requirement if repository style supports fixed capacity;
- failure before any caller-side write occurs.

The planner should be allocation-free or fixed-capacity if reasonably consistent with existing repository foundations.

Do not bake the current 0x8040xxxx addresses into the reusable module.

The freestanding adapter supplies current page-table truth.


TRANSFER SEMANTICS

Use deliberately native, narrow semantics.

Suggested bounded maximum transfer size for the QEMU probe:

32 or 64 bytes.

Choose one fixed maximum and make it explicit.

Suggested deterministic error model:

- invalid/overflowing range;
- unmapped;
- not user-accessible;
- not readable;
- not writable;
- too many segments / exceeds bounded transfer limit.

Exact error names should follow repository style.

Zero-length policy must be explicit and tested.

A simple policy is:

zero length succeeds without resolving/dereferencing memory

but use repository conventions if an existing range primitive strongly suggests another contract.

Do not silently truncate.

Do not partially copy beyond the requested length.

SUGGESTED USER-SIDE SEQUENCE

Reserve a fixed small stack block, for example 96–160 bytes inside the existing U RW page.

Define deterministic slots, for example:

slot A: input payload
slot B: output destination
slot C: guard bytes surrounding output destination
slot D: guard bytes for rejected-write proof
slot E: status/result sentinels

Use a memorable deterministic input payload such as 16 bytes:

"zig-user-memory!"

or any exact fixed byte sequence of the chosen length.

Do not rely on a C string terminator unless it is part of the tested length.

First service:

- user writes input payload into slot A;
- a0 = pointer to slot A;
- a1 = input length;
- optionally a2 = fixed operation marker only if needed by the bounded state machine;
- execute userMemoryProbeCopyInEcall.

Supervisor:

- independently recognizes the expected first Batch 21 ECALL PC;
- validates pointer + length;
- builds a read plan;
- copies exact bytes into trusted supervisor scratch storage;
- verifies/records exact bytes or deterministic digest;
- returns bounded status/result in register(s);
- SRET back to ELF-derived userMemoryProbeAfterCopyIn.

User:

- verifies returned success marker;
- establishes output destination guards;
- passes pointer + length for slot B;
- executes userMemoryProbeCopyOutEcall.

Supervisor:

- validates complete write range first;
- builds write plan;
- writes deterministic reply payload from supervisor storage through resolved physical segments;
- returns success;
- SRET to ELF-derived userMemoryProbeAfterCopyOut.

User:

- verifies every reply byte;
- verifies surrounding guards were not changed;
- prepares an intentionally invalid write request;
- executes userMemoryProbeRejectEcall.

Suggested real-machine rejection:

attempt a write whose first byte lies in the existing U RX code page, or a range that begins in/enters a non-writable page.

The handler must reject it before mutation.

Do not actually overwrite user code.

User then verifies a nearby writable guard remains unchanged if the rejected range would otherwise have crossed into it.

Finally:

- set a terminal marker;
- execute userMemoryProbeTerminalEcall;
- fail-stop after the terminal ECALL if execution unexpectedly returns again.

TRUSTED TRAP STACK

Every Batch 21 U-origin trap must retain the Batch 19/20 safety invariant:

first instruction of the dedicated user-origin trap path:

csrrw sp, sscratch, sp

No load/store/global access/C call may precede that swap.

Repeated returns to U-mode must rearm sscratch with the trusted trap-stack top before SRET.

The verifier should require that repeated Batch 21 trap frames land at the same expected supervisor-only frame address when using the same fixed stack geometry.

Unexpected nesting remains out of scope; interrupts stay disabled during the bounded proof.


FULL USER CONTEXT

Reuse the Batch 20 full-enough TrapFrame discipline.

Do not regress to saving only calling-convention registers.

Trap-return correctness is architectural, not a normal function-call contract.

The supervisor may update only the intended return registers and sepc/sstatus fields before returning to U-mode.

Selected non-result user registers should be sentinel-checked across at least one transfer return.


FAILURE ATOMICITY

This batch must distinguish validation from mutation.

For copy-OUT:

1. validate the complete logical range;
2. obtain the complete bounded transfer plan;
3. only after the entire plan succeeds, perform writes.

A later segment permission failure must not leave earlier user bytes modified.

Mechanically prove at least one failure-atomic rejection in unit tests.

Prefer a QEMU proof too using the RX-code-page rejection geometry if practical.

For copy-IN, failure should similarly avoid exposing a partial trusted result as a successful completed transfer.

Use scratch-buffer commit semantics if needed:

- copy into temporary trusted buffer;
- mark/consume result only after full transfer succeeds.

REAL-MACHINE COPY-IN PROOF

Use a deterministic user payload whose exact bytes are known independently to the verifier.

A good proof includes:

input_ptr = exact bounded stack VA
input_len = exact small constant
resolved segments = mechanically recomputed from final raw PTE truth
trusted destination = supervisor .bss scratch buffer
copied bytes = exact expected bytes

The verifier should derive expected bytes from a stable test constant or ELF-visible data, not merely trust a machine-emitted digest.

If a digest is used, compute the digest independently in the verifier and compare it to emitted raw bytes or independently known source bytes.

For a small payload, emitting exact hexadecimal bytes is simpler and stronger.


REAL-MACHINE COPY-OUT PROOF

Use a second bounded user stack slot that begins with guard/sentinel bytes.

Supervisor validates the complete target range and writes a deterministic reply such as:

"ALPZ-USER-OK"

or another fixed byte sequence.

The user probe must verify every byte after SRET.

The supervisor may later inspect the same physical stack frame only for evidence after the user probe has completed.

The verifier must independently compare the output bytes and guards.


REAL-MACHINE REJECTION PROOF

Prefer a permission failure that cannot accidentally succeed.

Strong candidate:

request copy-OUT into the U RX code page.

The planner must see U=1 but W=0 and return a deterministic not-writable rejection.

No code byte may be modified.

If demonstrating cross-page failure atomicity is practical, use a range whose later page is non-writable and prove bytes in any earlier writable fragment remain untouched because all validation completed before mutation.

Do not destabilize the active executing template merely to make a more theatrical rejection case.

Safety and clarity beat novelty.


UNIT-LEVEL CROSS-PAGE PROOF

Even if the QEMU success cases remain stack-local, the reusable planner must prove page splitting independently.

Construct deterministic fake mappings where:

virtual page A → physical frame X
virtual page B → physical frame Y

with X and Y noncontiguous.

Plan a range beginning near the end of A and ending inside B.

Require exactly two ordered segments with correct offsets and lengths.

Then mutate permissions on B and prove the whole plan fails before any copy-out mutation.

This is the reusable guarantee future user buffers will rely on once address spaces grow beyond two pages.

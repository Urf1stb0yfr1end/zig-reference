USER PROBE CONSTRUCTION

There is no userspace ELF loader yet. Do not invent one in Batch 19.

Build one tiny deterministic, relocation-safe user probe and copy its instruction bytes into the allocated user-code physical frame through the supervisor identity mapping before entering U-mode.

Preferred probe properties:

- bounded size far below one page;
- position-independent after copying;
- no kernel-symbol address references;
- no SBI calls;
- no libc;
- no heap;
- no PC-relative reference to kernel data;
- no privileged instructions;
- no syscall-number convention;
- uses only fixed register sentinels and the supplied user stack;
- stores one sentinel to the user stack and reads it back;
- places known values in a few general registers;
- executes exactly one ECALL as the intentional return signal;
- contains a fail-stop instruction/loop after ECALL so accidental return to U-mode after the one-shot trap cannot silently look successful.

A strong implementation is a small assembler-defined template with ELF-visible begin/end/ECALL labels whose bytes are copied into the user-code frame.

The verifier should derive the expected ECALL offset from those canonical template symbols and require the trapped sepc to equal:

user_code_va + (template_ecall - template_begin)

Do not trust a machine-emitted expected_ecall field without independently checking the template relationship.

If pseudo-instructions are used, prove the emitted template still contains no relocation-dependent reference that becomes wrong after copying.


INSTRUCTION AND TRANSLATION SYNCHRONIZATION

This is mandatory correctness work.

The supervisor writes new instruction bytes into memory and then causes U-mode to fetch them through a new executable virtual mapping.

Therefore do not rely on QEMU cache friendliness.

Required sequence:

populate/verify user code physical frame
→ install user code + user stack PTEs
→ execute the architecturally appropriate SFENCE.VMA boundary for the new translations
→ execute FENCE.I before U-mode instruction fetch
→ enter U-mode

Reuse the existing SFENCE.VMA machinery.
Search for an existing FENCE.I primitive before adding code. If none exists, one explicit RISC-V adapter-level FENCE.I is acceptable for this bounded single-hart proof; record that it is a local-hart instruction synchronization boundary, not a multi-hart I-cache protocol.

Evidence must distinguish translation synchronization from instruction synchronization.

ONE-SENTENCE PREVENTABLE:

Fresh executable bytes are not proven executable correctly merely because QEMU happened to fetch the bytes you just wrote; synchronize instruction fetch explicitly.


TRUSTED SUPERVISOR TRAP STACK

This is the most important safety requirement in Batch 19.

RISC-V does not automatically replace sp when a U-mode trap enters S-mode.

The current supervisor trap entry was designed for traps whose interrupted sp is already a supervisor stack pointer. Do NOT enter U-mode and let the first trap frame be written on the user-controlled stack.

The U-mode trap path must switch to trusted supervisor-only memory before its first trap-frame load/store.

Use sscratch or an equivalently standard, mechanically justified RISC-V mechanism.

A strong bounded design is:

- keep the existing total 64 KiB linker-reserved supervisor stack extent;
- carve a small fixed trap-stack region from that existing reservation rather than allocating another physical frame;
- preserve the historical __stack_bottom/__stack_top total-range meaning;
- introduce explicit linker symbols for the normal supervisor stack ceiling and dedicated U-trap stack begin/end/top;
- start ordinary supervisor execution below the reserved trap-stack region;
- set sscratch to the dedicated trap-stack top immediately before entering U-mode;
- on trap from U-mode, use a register-only stack swap such as the canonical csrrw sp,sscratch,sp pattern before any memory store;
- record the original user sp from sscratch only after the temporary register used for that read has itself been safely saved;
- place the complete TrapFrame only on the supervisor-only trap stack.

Do not simply point sscratch at __stack_top while freestandingMain may already occupy the same stack area.
Do not rely on undocumented spare bytes above or below the current stack pointer.
Do not allocate a user-accessible trap stack.

The verifier must prove:

- trap-frame address lies inside the declared trusted trap-stack range;
- the leaf containing that trap frame has U=0 and RW/NX supervisor permissions;
- trapped user sp lies inside the declared user stack page;
- no trap-frame memory write is required before the stack swap.

Nested traps/interrupts remain out of scope. Keep interrupts disabled across this bounded U-mode probe so the dedicated one-shot trap stack cannot be confused with a general nested-trap design.


S→U TRANSITION

Enter U-mode architecturally, not by labeling S-mode code as user code.

Immediately before the transition, prove/establish at minimum:

- active satp remains Sv39 with the Batch 18 owned root;
- stvec points to the dedicated bounded user-trap entry;
- sscratch contains the trusted supervisor trap-stack top;
- supervisor interrupts are disabled for the bounded probe;
- sstatus.SPP is cleared so SRET returns to U-mode;
- SPIE/SIE policy is explicit and does not accidentally enable asynchronous user-time interrupts;
- SUM remains disabled unless a specific documented operation truly requires it;
- sepc contains the user-code entry VA;
- user sp contains the aligned top of the user stack page;
- the transition executes SRET.

Preserve enough supervisor call state to return safely to the exact continuation after the U-mode trap. Do not assume user general registers will preserve supervisor caller/callee state.

A small assembly trampoline may save the normal supervisor continuation state, enter U-mode, and later restore it after the dedicated trap path returns to S-mode.

Keep this bounded and explicit.


U→S RETURN SIGNAL

The user probe executes exactly one ECALL.

The dedicated user-trap path must prove:

- interrupt bit = 0;
- scause = 8 (environment call from U-mode);
- trapped sstatus.SPP = 0, mechanically proving the interrupted privilege was U;
- trapped sepc equals the independently derived copied-template ECALL VA;
- trapped user sp is in the user stack range;
- selected user register sentinels match the probe contract;
- the user stack sentinel was actually written/read as expected;
- the trap frame itself resides on the supervisor-only trap stack.

This is not a syscall dispatcher.

Do not decode a7 as a syscall number.
Do not expose a syscall table.
Do not copy arbitrary user pointers.
Do not return a syscall result to U-mode.

After recording the one-shot expected trap, deliberately transfer to a known supervisor continuation. A clean approach is to set the saved return state for S-mode and execute SRET into a supervisor resume label while restoring the saved supervisor stack/callee state.

Record exactly how SPP/SPIE/SIE are prepared for that supervisor continuation.

Any unexpected user-origin exception/interrupt/cause/sepc must fail closed and must not inherit the ECALL success policy.

PRIMARY OBJECTIVE 2: STANDARDIZED DIAGNOSTIC PROTOCOL V1

Establish a minimal diagnostic protocol that reduces debugging rediscovery without creating a new private debugging language.

The protocol must use ordinary software-engineering terminology. Stable zig-reference identities should supplement common language, not replace it.

Use stable diagnostic IDs of the form:

ZIGREF-CATEGORY-SPECIFIC-NAME

Keep the category vocabulary small and boring. The initial controlled category set should be limited to concepts such as:

ENV
INPUT
BOUNDS
ARITH
OWNERSHIP
LIFETIME
STATE
RESOURCE
PARSE
DEPENDENCY
COMPOSITION
PLATFORM
PORTABILITY
DETERMINISM
EVIDENCE
CONTRACT
INDEX
TOOLING
VALIDATION

Do not add categories merely to make the list look complete. If the existing schema or implementation already has a better constrained representation, extend it minimally rather than introducing parallel taxonomy.

A diagnostic record must be sufficient for a cold agent to answer, where applicable:

What happened?
What component or operation is affected?
What rule or invariant was violated?
What was observed?
What was expected?
What known evidence demonstrates the failure?
What repair is canonical or recommended?
What exact command validates the repair?
What files are the minimum useful inspection locations?

Preserve native Zig errors and ordinary command output. A ZIGREF diagnostic is an indexable stable identity and repair-memory hook, not a replacement for native error text.

Do not invent diagnostics for hypothetical failures that have no real source, test, fixture, contract, or repository failure mode behind them.

Reuse the existing agent diagnostic machinery and generated/agent/diagnostics.json wherever possible. Avoid a second diagnostic database or opaque state.

The existing command:

python3 tools/query-reference.py agent diagnostic ID

must remain the canonical cold lookup path for a known diagnostic ID unless there is a strong repository-native reason to refine it.

Where a known diagnostic exists, its projection should expose the cheapest sufficient repair information without forcing the agent to read implementation source first.

Add only enough schema/tooling changes to make the protocol consistent and enforceable. Do not build a general debugger, LSP, daemon, network service, database, or interactive shell.

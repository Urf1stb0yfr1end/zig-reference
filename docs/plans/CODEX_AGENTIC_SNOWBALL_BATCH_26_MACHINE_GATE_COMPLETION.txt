GATE D — REAL PT_INTERP / ET_DYN INTERPRETER HANDOFF
======================================================================

This gate closes the architecture gap repaired in projects 54/59.

Required flow:

    main executable bytes
        -> validated ELF plan
        -> derive PT_INTERP from main ELF
        -> resolve interpreter path through project 58
        -> validate interpreter ELF
        -> choose non-overlapping main/interpreter mappings
        -> apply correct ET_DYN load bias
        -> construct justified Linux startup facts
        -> enter interpreter at correctly biased interpreter entry

Requirements:

- derive the interpreter pathname from validated main ELF data;
- resolve interpreter bytes through the same filesystem path;
- reject absent/malformed/recursive interpreter cases;
- represent ET_DYN load bias correctly in actual mapping and entry calculation;
- do not jump to raw ET_DYN `e_entry` when the image has been relocated by a load bias;
- do not perform userspace relocation in the kernel;
- provide only startup/auxv facts required by the chosen proof, such as `AT_ENTRY`, `AT_BASE`, and `AT_PHDR` when justified;
- interpreter entry and main entry must remain distinguishable and independently checkable;
- prove that control reaches the interpreter path and that the handoff contains the main-image facts required by the selected fixture.

The proof fixture may use a deliberately tiny interpreter designed for deterministic verification. It need not be a complete production dynamic linker. The invariant being proved is correct kernel handoff, not full userspace relocation support.

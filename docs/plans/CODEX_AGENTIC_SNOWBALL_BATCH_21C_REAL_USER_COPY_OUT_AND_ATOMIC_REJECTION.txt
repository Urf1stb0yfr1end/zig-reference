LATER-PAGE FAILURE / ATOMICITY PROOF

This is the most important new Batch 21C pressure.

Use a destination range whose prefix lies in the valid writable stack page but whose suffix reaches the immediately following unmapped page.

Recommended geometry:

start:
0x80403000 - 8

length:
16

Therefore:

first 8 bytes:
inside U RW/NX stack page

next 8 bytes:
starting at 0x80403000, outside the currently mapped user pages

Before issuing this rejected request, U-mode must write a deterministic 8-byte sentinel into the valid writable prefix.

The supervisor must:

1. call bounded-user-memory-transfer-plan in write_to_user mode;
2. allow the planner to validate the first writable page;
3. encounter the second page as unmapped;
4. receive the deterministic planner error;
5. perform ZERO destination writes because no complete plan was returned.

After returning to U-mode, user code must independently read the valid 8-byte prefix and prove the sentinel is unchanged.

The supervisor/verifier should also record enough evidence to establish:

- requested VA and length;
- first page was the real mapped U RW page;
- second page was unmapped;
- expected rejection variant;
- no copy segment sequence was consumed for writing;
- valid-prefix bytes before == after;
- no trap/page fault escaped the bounded service;
- U-mode successfully resumed after the rejected request.

This is the required all-or-nothing proof.

Do NOT implement a design that copies the first page and only then discovers the second-page error.

The whole point of the planner is validation before mutation.

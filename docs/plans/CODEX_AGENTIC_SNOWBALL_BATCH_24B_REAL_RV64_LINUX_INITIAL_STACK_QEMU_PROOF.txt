MISSION

Batch 23 proved a real separately built RV64 ET_EXEC userspace ELF with executable code, initialized writable data, non-empty BSS, real U-mode mutation, and trusted U→S return under strict repeated QEMU evidence.

Batch 24A then created the reusable bounded-rv64-linux-initial-stack-plan module. It deterministically owns the exact byte image for [initial_sp, stack_top), containing argc, argv, envp, ordered auxv pairs, required NULL/AT_NULL sentinels, zero padding, NUL-terminated strings, exact in-image guest pointers, and a 16-byte-aligned initial SP. It explicitly does not write guest memory or execute under QEMU.

Batch 24B must prove exactly one new machine fact:

The existing Batch 24A planner can be consumed unchanged by Alpz to materialize one exact Linux-style initial process stack into real mapped U RW/NX memory, enter a separately built RV64 ELF at planner-derived ELF e_entry with exactly planner.initial_sp, and have real U-mode code independently parse and validate argc/argv/envp/auxv and their pointer/string relationships before returning through the trusted supervisor trap boundary under strict mutation-tested two-QEMU evidence.

The decisive boundary is:

    settled stack policy in project 55
                ↓
    exact planner-owned byte image
                ↓
    real mapped U RW/NX stack memory
                ↓
    SRET with SP = planner.initial_sp
                ↓
    independently parsing RV64 U-mode ELF
                ↓
    successful terminal ECALL
                ↓
    strict external proof + second QEMU run

Do not begin Batch 25 Linux syscall ABI work in this run.

U-MODE MUST INDEPENDENTLY VALIDATE

The U-mode fixture must validate from raw memory, not from kernel-emitted metadata:

1. initial SP is 16-byte aligned;
2. argc is the exact expected count;
3. argv pointers appear in order;
4. argv NULL sentinel exists exactly where expected;
5. envp pointers appear in order;
6. envp NULL sentinel exists;
7. auxv entries appear in the expected order for this bounded fixture;
8. AT_NULL,0 terminates auxv;
9. every argv/env pointer lies within the mapped startup-stack image/range;
10. every pointer reaches the exact expected NUL-terminated bytes;
11. AT_EXECFN equals the exact argv[0] pointer if used;
12. AT_PAGESZ equals 4096 if used;
13. AT_ENTRY equals the actual fixture ELF entry relationship, preferably derived from the fixture symbol/linked image rather than a second kernel constant;
14. no expected relationship depends on a kernel-provided success flag.

Where practical, preserve the Batch 23 initialized-data/BSS check and BSS mutation too. If retained, require the supervisor to observe the real mutation in the actual writable backing frame exactly as Batch 23 did.

The guest may set deterministic register markers after successful independent checks so the supervisor/verifier can prove which path executed. Those markers are evidence of successful guest validation, not substitutes for external proof of the stack bytes.

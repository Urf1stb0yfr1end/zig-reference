LINKER PAGE-DOMAIN RULE

Strict per-page permissions require strict per-page ownership of section meaning.

The current Batch 17 image begins at 0x80200000 and maps the page-rounded continuation span, but the linker script does not yet establish page-separated text/rodata/writable domains.

Do not pretend a page is both read-only and writable merely because two ELF sections happen to share it.
Do not label a mixed text/data page RX or RW and call the split complete.

Preferred design:

- extend the existing freestanding linker script with explicit page-aligned permission-domain boundaries;
- preserve __image_begin and __image_end truth;
- expose repository-consistent symbols for the text, rodata, and writable domains;
- align transitions between permission classes to 4096 bytes;
- avoid gratuitous holes beyond the page padding required to make permissions truthful;
- keep the existing 64 KiB stack and linker-owned physical page pool inside the writable/non-executable supervisor domain;
- let ELF symbols remain the canonical source of ranges;
- do not duplicate hard-coded section addresses in Zig or Python.

A strong shape is conceptually:

[image begin]
[text domain: entry + trap + all executable text]      RX, U=0
[page boundary]
[rodata domain]                                        R,  U=0
[page boundary]
[data + BSS + active stack + owned page pool]          RW, U=0
[image end]

Exact symbol names should follow repository conventions and must be mechanically inspected from the ELF by the verifier.

If a section is empty, preserve truthful page-domain arithmetic rather than inventing fake content.

ONE-SENTENCE PREVENTABLE:

A permission split is not real if ELF sections with incompatible permissions still share the same hardware page.

MISSION

Advance the sealed Batch 19 RISC-V machine boundary by exactly one architectural pressure:

prove one bounded U-mode ECALL that enters S-mode on the trusted supervisor trap stack, performs one fixed register-only supervisor service, deliberately returns to U-mode through SRET at an independently derived continuation PC, proves that user execution really resumed and observed the supervisor-produced return value, then executes one second terminal U-mode ECALL that returns deliberately to the known supervisor continuation.

This batch is the first proof of:

U-mode
→ ECALL
→ trusted S-mode trap handling
→ supervisor changes a user return register
→ SRET back to U-mode
→ user instructions execute after the return
→ second bounded U-mode ECALL
→ known S-mode continuation

Do not turn this into Linux syscall work.

Do not build a syscall table.

Do not add Linux syscall numbers.

Do not add user pointers or copy helpers.

Do not add processes, ELF userspace loading, VFS, file descriptors, mmap, brk, signals, futexes, or Alpine work.

The Batch 20 service exists only to prove the trap/return machinery.

FIXED REGISTER-ONLY SERVICE CONTRACT

Use one deliberately tiny register-only service so the batch proves argument capture and a kernel-produced return value without introducing user-memory copying.

Recommended contract:

input a0 = 0x20
input a1 = 0x19

supervisor result:
a0 = 0x39

This may simply be bounded addition of the two fixed arguments.

The exact arithmetic is not the milestone. The milestone is that the result is produced in S-mode and is observed by resumed U-mode code.

Do not publish this as a stable syscall ABI.

Do not assign it a Linux syscall number.

Do not create an a7 dispatch table.

Do not call it POSIX.

Do not create a generic registration mechanism.

The handler should recognize the first service operation from the independently known first ECALL PC plus the expected bounded register state.

The second ECALL is a terminal proof signal, not a second service.


USER-SIDE PROOF SHAPE

A strong copied template does approximately this:

- establish a bounded user stack reservation, for example 32 bytes;
- write a pre-service sentinel into its own user stack;
- establish service inputs a0=0x20 and a1=0x19;
- establish selected non-result register sentinels;

- resume exactly at userServiceProbeAfterService;

Use only relocation-safe local branches/labels.

Suggested user stack evidence can occupy fixed slots inside the one already-mapped stack page, for example:

slot 2: post-return sentinel

Exact offsets/values may differ if the implementation has a better bounded layout. Record them explicitly and verify them independently.


FIRST ECALL — TRUSTED U→S ENTRY

The Batch 20 service trap path must preserve the core Batch 19 safety rule:

RISC-V does not automatically replace sp on U→S trap.

Therefore the first instruction of the Batch 20 user-origin trap entry must be a register-only trusted-stack exchange equivalent to:

csrrw sp, sscratch, sp

No load.
No store.
No stack allocation.
No C call.
No global access.

may precede that swap.

Only after the swap may the trap path allocate/write a supervisor TrapFrame.

Keep interrupts disabled across this bounded probe.

Nested traps remain out of scope.


COMPLETE ENOUGH USER CONTEXT FOR RETURN

Batch 19 did not need a general return-to-user context because its one ECALL terminated the U-mode probe and transferred to S-mode.

Batch 20 does.

The Batch 20 trap path must save enough integer state to resume the interrupted U-mode execution correctly.

Prefer using the existing 288-byte TrapFrame layout and actually populating the complete integer register state needed by the return path rather than inventing a second incompatible frame shape.

At minimum, mechanically preserve all user integer registers whose values may be live across the trap, with x2/original user sp captured through sscratch after the original scratch register used to read it has itself been safely saved.

A strong implementation saves x1–x31, with x2 reconstructed from sscratch, plus:

- sepc;
- sstatus;
- scause;
- stval.

x0 is architecturally zero.

If some registers are intentionally not stored, justify exactly why they cannot be live and add evidence. Do not rely on C calling conventions to preserve user state across a trap.

This is a privilege-return boundary, not an ordinary function call.


FIRST TRAP HANDLER POLICY

For the first Batch 20 ECALL, require mechanically:

- interrupt bit = 0;
- scause = 8;
- trapped SPP = 0;
- trapped sepc equals the ELF-derived copied service ECALL VA;
- trapped user sp lies inside the existing user stack page;
- expected fixed service inputs are present;
- selected register sentinels are present;
- TrapFrame lies wholly inside the dedicated supervisor-only trap stack;
- the trap-stack leaf is U=0 RW/NX.

Then perform only the fixed register service:

result = 0x20 + 0x19 = 0x39

Write the service result into the saved user a0 slot in the trusted TrapFrame.

Do not write through a user pointer.

Do not set SUM.

Do not access user virtual memory from S-mode as part of the service.


ELF-DERIVED RETURN PC

Do not return to U-mode by blindly doing sepc += 4 and assuming that is sufficient evidence.

ECALL is architecturally fixed-width, but this repository can prove more.

Independently derive from the built ELF:

userServiceProbeTemplateBegin
userServiceProbeServiceEcall
userServiceProbeAfterService

Compute:

service_ecall_va = user_code_va + (service_ecall_symbol - template_begin_symbol)

service_resume_va = user_code_va + (after_service_symbol - template_begin_symbol)

Require the trapped first sepc to equal service_ecall_va.

Set the trusted saved return sepc to service_resume_va.

Require service_resume_va to be strictly after the first ECALL and before the terminal ECALL.

The runtime may emit these values as evidence, but the verifier must recompute them from ELF symbols and reject disagreement.


SSTATUS POLICY FOR RETURN TO U

Before the first trap executes SRET back to U-mode, mechanically prepare the saved sstatus so:

- SPP = 0;
- SIE remains disabled for this bounded proof;
- SPIE policy is explicit and must not accidentally enable user-time asynchronous interrupts;
- SUM = 0;
- unrelated preserved bits are not casually destroyed.

Do not hardcode an entire replacement sstatus word if a masked update preserves more truthful state.

Record the trapped value and the return-prepared value separately.

The verifier must decode the relevant bits independently.


REARM THE TRUSTED TRAP STACK BEFORE USER RETURN

The critical Batch 20 novelty is not merely changing sepc. The machine must be safe for the second U-origin trap too.

On first-trap return to U-mode:

- restore the intended saved user registers, with a0 containing the supervisor result;
- restore the prepared user sepc/sstatus;
- unwind the supervisor TrapFrame so supervisor sp is back at the trusted trap-stack top;
- perform the register-only swap that restores user sp and places the trusted trap-stack top back into sscratch;
- execute SRET.

A canonical shape is the inverse of the entry swap:

trap entry:
    csrrw sp, sscratch, sp

return after frame unwind:
    csrrw sp, sscratch, sp
    sret

provided the register and frame ordering is proven correct.

After that return:

sp must be the original bounded user sp;
sscratch must again contain the trusted supervisor trap-stack top.

There is no supervisor instruction window in U-mode to read sscratch directly, so the strongest behavioral proof is that the second U-mode ECALL again lands at the expected trap-frame address inside the trusted trap stack.

If the same fixed trap-stack top and same frame size are reused, require the two recorded Batch 20 trap-frame addresses to be identical unless there is a documented reason otherwise.

This is powerful evidence that the trusted-stack convention was correctly rearmed.


PROVE USER EXECUTION AFTER THE FIRST SRET

Do not call Batch 20 successful merely because the supervisor prepared a return frame.

The user probe must prove it actually resumed.

After userServiceProbeAfterService executes, user code must:

- observe a0 == 0x39;
- verify selected non-result register sentinels;
- write the service result into its own stack;
- write a distinct post-return sentinel;
- reach the independently derived terminal ECALL site.

If the result or preserved state is wrong, the user probe must fail-stop rather than execute the terminal success ECALL.

Thus reaching the second expected U-mode ECALL is itself evidence that real user instructions executed after the first supervisor SRET.


SECOND TERMINAL ECALL

The second Batch 20 ECALL is a bounded completion signal.

It is not another service.

The second trap must prove:

- it is the second and only second Batch 20 U-origin trap;
- interrupt bit = 0;
- scause = 8;
- trapped SPP = 0;
- trapped sepc equals the independently ELF-derived terminal ECALL VA;
- user sp remains inside the one existing user stack page;
- the expected terminal register marker is present;
- selected preserved state shows the first return completed;
- the trap frame again lies wholly inside the supervisor-only trap stack;
- no third Batch 20 U-origin trap occurs.

The terminal ECALL must not return to U-mode.

Instead deliberately transfer to the known S-mode continuation, using the saved ordinary supervisor stack/callee state established before initial Batch 20 entry.

Set SPP deliberately for that supervisor continuation and record the exact policy.

Any unexpected cause, PC, trap count, or privilege state must fail closed.

FENCE TRUTH

Batch 20 overwrites executable bytes in an already-mapped physical page and later fetches them through the existing executable U mapping.

Therefore FENCE.I is mandatory before entering the new probe.

Translation synchronization is separate.

If no PTE changes occurred, SFENCE.VMA is not required merely because instruction bytes changed.

The evidence and report should explicitly teach this distinction:

PTE unchanged
→ no translation invalidation required

instruction bytes changed
→ FENCE.I required before instruction fetch

Do not rely on QEMU cache friendliness.

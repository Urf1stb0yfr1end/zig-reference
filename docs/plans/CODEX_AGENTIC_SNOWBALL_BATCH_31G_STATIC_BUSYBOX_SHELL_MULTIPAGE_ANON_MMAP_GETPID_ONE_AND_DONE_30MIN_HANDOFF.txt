================================================================================

non-fixed RW anonymous mapping slice.

Generalize only as required to support a checked, bounded request spanning

The permanent mechanism must remain Linux-neutral.

BAD:

    if length == 8192 and artifact == BusyBox: allow it

BAD:

    const BusyBoxShellPages = 2

BAD:

    Morphic mapping flags = Linux mmap flags

GOOD:

    Linux mmap adapter
      -> validates/translates Linux request
      -> neutral checked page-count/range request
      -> bounded virtual-range reservation
      -> bounded backing ownership for N pages
      -> map N pages with requested neutral permissions
      -> rollback atomically on any failure
      -> return neutral mapping base

Requirements for the neutral multi-page mechanism, insofar as the observed
request demands them:

- checked length-to-page-count conversion;
- reject zero length;
- reject arithmetic overflow;
- page-aligned virtual placement;
- contiguous virtual range reservation for N pages;
- explicit bounded backing-page ownership for N pages;
- collision detection against image, stack, brk, prior runtime mappings, and
  reserved regions;
- no partial live mapping if backing/reservation/page-table preparation fails;
- zero anonymous accessible backing before exposure to userspace;
- install only the requested R/W/X-neutral permissions;
- preserve W+X prohibition;
- deterministic bounded failure when capacity is insufficient;
- release/rollback all newly claimed backing on failure;
- preserve existing one-page behavior.

Do not assume physical contiguity is required merely because virtual
contiguity is required. Use the smallest existing neutral backing model that
can correctly map the requested virtual pages.

Do not hardcode the current returned addresses 0x106000 or 0x107000 into the
architecture.

================================================================================

Linux/RV64 syscall 172 is getpid.

The observed shell continued after Morphic returned -ENOSYS, then failed on the
8192-byte mmap. Therefore getpid is currently an unsupported request, but it is
NOT yet proven to be the fatal blocker.

First repair the earliest demonstrated fatal boundary.

After multi-page mmap succeeds, retry the exact shell immediately.

Only implement getpid in this campaign if one of the following becomes true:

A. golden differential plus control-flow evidence proves the returned PID is
   semantically consumed in a way required for shell completion; or

B. after the mmap repair, exact shell pressure demonstrates getpid itself is
   now the first causal blocker.

If required, keep Linux syscall-number/errno semantics at the Linux edge and
back them with a neutral Morphic task/process identity concept. Do NOT make
Morphic process identity equal Linux pid_t unless existing architecture has
already intentionally established that equivalence.

If a stable neutral task identity already exists, adapt it. Do not invent a
second identity system merely to satisfy getpid.

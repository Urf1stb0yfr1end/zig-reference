MAPPING POLICY

The first active Sv39 address space should be intentionally small and truthful.

Do not install a gratuitous 1 GiB identity map merely because it is easy.
Do not map arbitrary QEMU RAM as valid kernel memory.
Do not map all MMIO ranges unless the current execution path actually requires them.

Discover the exact current freestanding continuation footprint from the linker/ELF and source.

Map the minimum page-aligned regions necessary for the kernel to survive the transition and continue the proof, including as actually required:

- executing code after satp activation;
- read-only data used afterward;
- writable data/BSS used afterward;
- active stack;
- linker-owned physical page pool and page-table pages if they remain accessed by virtual address after activation;
- any real device/MMIO page genuinely used by the post-activation console or shutdown path, but only if current source proves it is required.

Prefer 4 KiB mappings for the first proof because they make exact coverage and permissions mechanically visible and avoid implying ownership of unused surrounding megabytes.

Use the existing Builder and page-table entry Permissions semantics rather than hand-encoding PTEs.

Do not silently make the whole image RWX if current ELF/linker information permits a narrow and mechanically provable split at modest complexity.
At minimum document exactly what permissions are installed and why.
If the first bounded proof must temporarily use a simpler permission policy to preserve continuity, keep the claim narrow, record the gap explicitly, and do not call it a hardened kernel mapping policy.

NON-IDENTITY TRANSLATION PROBE

An identity-mapped kernel continuing to run is necessary but should not be the only translation evidence.

Add one tiny, bounded, explicit non-identity mapping that proves the hardware is using the new page tables rather than merely surviving coincidentally at equal virtual/physical addresses.

Preferred proof shape:

- reserve/choose one real owned data frame not used as a page-table page;
- choose one canonical page-aligned virtual alias that does not overlap the kernel continuation mappings and is not already mapped;
- map exactly that virtual page to the selected owned physical frame with the existing Builder;
- record the selected virtual alias and physical frame as raw evidence;
- after satp activation, write a deterministic sentinel through the virtual alias;
- read the sentinel back through the alias;
- where safely possible, also prove the corresponding identity-mapped physical-pool address observes the same underlying data;
- independently verify the alias and physical addresses differ;
- independently verify the Builder/Walker mapping resolves the alias to the intended physical frame;
- keep accesses strictly within the one owned page.

Do not use an alias that could accidentally already be identity mapped.
Do not fabricate a high address without checking Sv39 canonicality.
Do not map arbitrary foreign physical memory.

The non-identity alias is a proof instrument, not a general kernel virtual-address ABI.
Do not name it as a stable user/kernel mapping convention.

# Agentic Snowball Batch 32M — ownership-correct dup2 and unchanged real-Alpine pressure

## Inherited proven frontier

Batch 32L is merged and is the source of truth for the inherited boundary.

The exact real BusyBox/musl/system-QEMU pressure crossed the previous Linux/RV64 F_DUPFD compatibility boundary. Unsupported fcntl commands now return Linux EINVAL so musl can fall back from F_DUPFD_CLOEXEC to F_DUPFD. The unchanged shell then reached the directly observed next boundary:

/bin/sh: dup2(10,1): Function not implemented

Do not re-solve F_DUPFD. Preserve its errno, ownership, failure-atomicity, lowest-free-descriptor, and reference-lifecycle guarantees.

The highest earned state is read-only Alpine plus persistent cwd and bounded writable runtime state, with real ash proven across F_DUPFD up to descriptor replacement. Playable Alpine is NOT yet earned.

## Primary objective

Implement the smallest ownership-correct Linux/RV64 descriptor-replacement behavior required by the directly observed dup2(10,1) pressure, then rerun the exact unchanged real-QEMU shell pressure.

The goal is not to implement a broad POSIX fd subsystem. The goal is to cross exactly the next causal compatibility boundary without weakening existing bounded-state or ownership invariants.

## Required semantics

First identify the actual Linux/RV64 syscall form emitted by the unchanged BusyBox/musl path. Do not assume the syscall number or wrapper if runtime evidence or the existing dispatcher says otherwise.

Implement the narrow dup2-equivalent semantics required by that observed path. The implementation must preserve Linux-visible behavior and the repository's bounded ownership model.

At minimum, prove and test the relevant behavior for:

- invalid source descriptor -> EBADF;
- valid source and target descriptor replacement;
- target already bound: release exactly the target's previous owned reference and replace it with the source resource;
- source resource retained exactly once when a distinct target alias is created;
- source == target behavior, if reachable through the actual syscall form, follows Linux semantics and does not perturb ownership;
- replacement is failure-atomic: if the operation cannot commit, descriptor topology and resource reference counts remain unchanged;
- replacing a target that aliases the same underlying resource remains reference-count correct;
- final closes release the resource exactly when the last owned descriptor reference disappears;
- out-of-range or otherwise impossible bounded target descriptors map to the correct Linux-visible failure for the implemented syscall form;
- no hidden allocation and no expansion of the bounded descriptor/resource model merely to make the test pass.

Do not place Linux errno policy into a neutral generic data structure if a focused Linux/RV64 adapter is the cleaner boundary. Reuse the Batch 32L adapter style or existing canonical primitives when they fit rather than duplicating ownership logic.

## Real pressure requirement

After focused tests and repository validation pass, rerun the same exact Alpine v3.22.0 RV64 artifact/live-console flow documented by Batch 32L. Use the unchanged artifact and unchanged shell command first:

Do not modify BusyBox, musl, the Alpine rootfs, or the command to evade the observed boundary.

If redirection succeeds, immediately test the next already-planned unchanged observations in causal order:

Stop at the first genuinely new causal blocker. Do not implement the next blocker in the same run unless it is inseparable from correct dup2 semantics or a tiny correctness repair required to make the just-added implementation valid.

Do not claim /tmp/hello read-back, pipelines, or Playable Alpine unless the real QEMU run actually proves them.
